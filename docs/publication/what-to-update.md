Все подготовленные файлы берите из `aml-ai-agent-system-rebuild` и переносите в отдельный клон `aml-ai-agent-system-publish` **с теми же относительными путями**. Например, `src/ui/app.py` из rebuild заменяет `src/ui/app.py` в клоне. Старый рабочий checkout и личный учебный стенд остаются на месте.

Список рассчитан относительно `main` репозитория [slim2115/aml-ai-agent-system-design](https://github.com/slim2115/aml-ai-agent-system-design), коммит `535940fd645c2b41d1ec167e8a98d58597adadf0`. Соответствие удалённой ветки проверено 16 ноября 2026 года. Если ветка изменится до публикации, сначала сопоставьте новые изменения с rebuild. Уже имеющиеся незакоммиченные изменения исходной рабочей копии не являются базой этого сравнения: для переноса используйте отдельный чистый клон.

## Комментарии к коммитам

После соответствующего `git add` и просмотра `git diff --cached` используйте ранее согласованные сообщения. Выполняйте по одному блоку из полной инструкции, не все команды подряд:

```powershell
git commit -m "chore(git): исключить локальный стенд и сохранить байты тестовых наборов"
git commit -m "feat(aml): добавить сервис расследований и стенд PostgreSQL, Swagger и Kafka"
git commit -m "test(qa): добавить Playwright, проверки моделей, Dark Factory и Windows CI"
git commit -m "docs: описать развёртывание, работу оператора и публикацию по блокам"
```

В указанных в таблице точках отправки команда одна: `git push origin main`. После push 2 и push 3 проверяйте GitHub Actions. Все commit и push выполняет владелец.

## Как перенести без ручного копирования сотен файлов

В полной инструкции сначала создаётся чистый клон. Затем помощник `scripts/release/publication_files.py copy-to` копирует только файлы из пяти согласованных списков, проверяет базовый коммит и сверяет байты. Новые пути добавляются, существующие заменяются; само удаление `tests/pytest.ini` выполняется отдельной командой `git rm` в QA-блоке. Помощник не создаёт коммиты и не делает push.

Перед каждым коммитом проверьте `git diff --cached --name-status`: `A` означает новый файл, `M` — заменяемый, `D` — удаляемый. Ожидаемое удаление только одно — `tests/pytest.ini`.

## Что остаётся локально

В GitHub отправляются **исходники учебного стенда**, чтобы другой инженер смог создать свою среду. Ваши базы, таблицы после упражнений, сообщения Kafka, Docker volumes, рабочее пространство DBeaver, модели, индексы, логи, `.env`, секреты и окружения Python остаются локально. Также не отправляются `var/`, `qa/progress.json`, исходный аудит и результаты из `verification/`, кроме пяти синтетических входов из `03-judge-fixtures.txt`.

Из `.rebuild/` публикуются только `origin.json` и `release-version.json`. Перечни этой инструкции будут актуализироваться при добавлении следующих этапов Dark Factory; перед отправкой используйте текущие файлы из rebuild.

# ADR-0005: Локальная (on-premise) LLM и векторная БД

## Статус
Accepted

## Дата
Июль 2026 г.

## Контекст
Система обрабатывает персональные данные клиентов (ФИО, ИНН, PAN) и банковскую тайну.
Требования ИБ банка категорически запрещают использование публичных зарубежных облачных API
(OpenAI, Anthropic и др.) — данные не должны покидать изолированный периметр (BRS Constraints, 152-ФЗ).

## Решение
Все компоненты генерации и поиска разворачиваются **локально (on-premise)**:
* LLM-инференс — локальная модель (например, Llama-3 / Mistral через Ollama) (NFR-10);
* embedding-модель для RAG — локальная, с поддержкой русского языка (Data Model раздел 4.4);
* векторная БД — локальная (ChromaDB / FAISS / pgvector);
* исходящие сетевые соединения во внешние LLM-сервисы отсутствуют (контролируется, NFR-10).

Для Production допускается переход на одобренные отечественные закрытые облачные контуры
(фиксируется как опция, не меняющая архитектуру).

## Рассматриваемые альтернативы
* **Публичные облачные LLM-API:** отвергнуто. Прямое нарушение требований ИБ банка и 152-ФЗ;
  риск утечки ПДн (RISK-SEC-04).
* **Только отечественное облако (без локального варианта):** допустимо для Production, но для PoC
  предпочтителен полностью локальный контур как наиболее безопасный и воспроизводимый.

## Последствия
* **Положительные:** соответствие 152-ФЗ и политике ИБ; данные не покидают периметр;
  воспроизводимость PoC на одной машине; отсутствие зависимости от внешних сервисов и их тарифов.
* **Отрицательные:** локальные модели уступают по качеству крупным облачным; требование
  к аппаратным ресурсам (GPU/RAM); целевой Faithfulness для PoC ограничен ≥ 90% (против ≥ 95%
  для Production с Fine-Tuning).
* **Риски:** недостаточное качество локальной модели для сложных кейсов; митигируется
  RAG-first (ADR-0004), guardrails и политикой отказа, а также метрикой Faithfulness.

* SRS: NFR-10.
* Data Model: раздел 4.4 (векторизация и индексация).
* Risks & Security: RISK-SEC-02, RISK-SEC-04.

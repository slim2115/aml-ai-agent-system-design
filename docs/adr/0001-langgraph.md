# ADR-0001: Оркестрация агента на LangGraph

## Статус
Accepted

## Дата
Июль 2026 г.

## Контекст
Агент реализует многошаговый цикл расследования: приём инцидента → агрегация данных (SQL) →
проверка полноты → RAG-поиск правил → генерация черновика → guardrail-проверки → HITL → экспорт.
Процесс содержит ветвления (явный отказ при недостатке данных, корректировка оператором) и
повторяющиеся итерации (цикл ReAct: Reason → Act → Observe).

Требуется механизм оркестрации, который обеспечивает:
* явное управление состоянием агента между шагами;
* детерминированные ветвления и циклы (контроль числа итераций ReAct);
* наблюдаемость (трассировка шагов для audit trail, NFR-11);
* расширяемость без перехода к multi-agent (multi-agent — в Out-of-Scope, BRS раздел 4.2).

## Решение
Использовать **LangGraph** (граф состояний) как основу оркестрации агента.
Каждый шаг процесса (валидация, SQL-запрос, RAG-поиск, генерация, guardrail) моделируется
как узел графа; переходы между узлами — как рёбра с условиями.

## Рассматриваемые альтернативы
* **Чистый LangChain (LCEL-цепочки):** отвергнуто. Линейные цепочки плохо подходят для
  циклов ReAct и условных ветвлений; управление состоянием и повторными попытками становится
  неструктурированным.
* **Самописный цикл оркестрации:** отвергнуто. Требует ручной реализации управления состоянием,
  трассировки и контроля циклов; выше риск ошибок и ниже воспроизводимость.
* **Multi-agent фреймворки (CrewAI / AutoGen):** отвергнуто. Избыточны для одного
  хорошо специфицированного агента; прямо исключены Out-of-Scope (BRS раздел 4.2) как scope-риск.

## Последствия
* **Положительные:** явная и аудируемая структура процесса; контролируемые ветвления
  (отказ, HITL-корректировка); ограниченное число итераций ReAct; лёгкая трассировка шагов.
* **Отрицательные:** зависимость от фреймворка и его версионирования; кривая обучения
  графовой модели состояний.
* **Риски:** изменение API LangGraph потребует миграции; митигируется фиксацией версии
  в зависимостях и инкапсуляцией узлов.

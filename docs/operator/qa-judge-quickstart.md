# Учебный LLM-as-a-Judge

Основная установка и полный рабочий цикл собраны в [единой инструкции](service-and-lab.md). Команды этого справочника выполняются из корня вашей копии. Упоминания сохранённых прогонов относятся к указанной дате; их локальные архивы не входят в обычный клон.

Инструкция для PowerShell в терминале VS Code, **21.10.2026**. Шаг 8 [плана QA](../rebuild/qa-practice-plan.md). Результаты измерения публикуются в отчёте шага (локальный материал: `verification/qa-step-08-2026-10-21/summary.md`); эта инструкция сама по себе не подтверждает успешный прогон.

Judge читает сохранённые отчёты шага 7 и варианты с намеренно внесёнными дефектами. Он оценивает один заданный критерий: подтверждение фактов источниками, полноту, порядок, ясность или уместность. Генератор отчётов повторно не вызывается. Исходный код, прежние данные и файлы моделей не переписываются; новые результаты сохраняются отдельно.

## 1. Подготовить материал для собственной оценки

Нужны существующее окружение `.venv`, набор `qa/datasets/judge-v1` и сохранённые артефакты шага 7. Для подготовки материала и последующего сравнения готовых оценок Ollama не требуется.

```powershell
# Терминал открыт в корне вашей копии проекта.
& .\.venv\Scripts\python.exe -I -B .\qa\tools\run_judge.py --prepare-only --output-dir var/qa/judge/my-materials
$LASTEXITCODE
```

Ожидаемый результат подготовки — **INCOMPLETE, код 3**: материал создан, модель ещё не оценивала кейсы. Каталог должен быть новым. Для повторного упражнения выберите другое имя; прежние свидетельства не удаляйте.

Откройте в VS Code только `var/qa/judge/my-materials/human-review-packet.md` и `human-review-template.json`. Сначала выполните собственную оценку, **до просмотра ответов Judge и ожидаемых меток**. Файл `dataset.json` содержит ожидаемые ответы и для независимой оценки не используется.

Сохраните заполненный шаблон как новый файл `var/qa/judge/my-materials/human-review-filled.json`:

- В `reviewer_id` укажите свой псевдоним, например `operator-01`; в `reviewed_at` — фактическое время оценки с часовым поясом, например `2026-10-21T18:30:00+03:00`.
- Сохраните версии, `dataset_sha256`, `case_id` и `criterion` из шаблона. В каждой оценке выберите `pass`, `fail` или `abstain`, добавьте краткое основание `rationale` до 500 символов.
- В `references` укажите существующий `ref_id` и точную непустую цитату `quote` из его фрагмента. Для `pass` и `fail` нужна хотя бы одна ссылка. Для пропущенного факта цитируйте его источник: отсутствующий текст отчёта процитировать нельзя.
- Для `single` оставьте `preference: not_applicable`. Для сравнения `pair` используйте `verdict: pass` и предпочтение `A`, `B` или `tie`; при нехватке оснований — `verdict: abstain`, `preference: abstain`. В паре `pass` означает завершённое сравнение, а не правильность обоих вариантов.

Оценивайте только запрошенный критерий по рубрике в материале. Не придумывайте оценки за другого человека. Можно заполнить часть кейсов: удалите незаполненные элементы из массива `ratings`, оставив хотя бы одну настоящую оценку. Неполный набор будет отмечен как **INCOMPLETE**, а не дополнен автоматически.

## 2. Выполнить оценку настоящей моделью

Запустите установленный Ollama с уже подготовленной `qwen2.5:14b`. Затем выполните:

```powershell
ollama list
& .\.venv\Scripts\python.exe -I -B .\qa\tools\run_judge.py --output-dir var/qa/judge/my-first-run
$qaJudgeExitCode = $LASTEXITCODE
Get-Content -LiteralPath 'var/qa/judge/my-first-run/result.json' -Raw
$qaJudgeExitCode
```

API сервиса, браузер, PostgreSQL и Kafka для упражнения не требуются. Скрипт проверяет digest подготовленной модели и обращается только к локальному Ollama. Во время измерения не меняйте код, набор и модель; завершите другие задания с LLM, чтобы уменьшить влияние очереди на время.

Полная серия планирует **20 запросов**: 9 учебных контролей `calibration`, 9 контролей другой семьи `heldout` и 2 сравнения одной пары с перестановкой A/B. Это связанные варианты трёх исходных сценариев, а не 20 независимых инцидентов. Ожидаемые метки заданы синтетическими изменениями и рубрикой; они не являются оценками AML-эксперта.

Настройки: `temperature=0`, `num_predict=512`, `num_ctx=32768`, seed явно не задан. На кейс предусмотрено до 180 секунд, на сбор серии — 1800 секунд; загрузка модели может замедлить первый запрос. Автоматических повторов нет, кеш оценок выключен. При ошибке неуспешный ответ остаётся частью результата. Параметры и поля длительности описаны в [Ollama `/api/chat`](https://docs.ollama.com/api/chat).

Для разбора меньшего объёма можно выполнить отдельный запуск:

```powershell
& .\.venv\Scripts\python.exe -I -B .\qa\tools\run_judge.py --phase calibration --output-dir var/qa/judge/my-calibration
```

Аналогично доступны `--phase heldout` и `--case-id J-001`. Это частичные прогоны: общий план остаётся 20 кейсов, отсутствующие наблюдения не считаются успешными. Не подбирайте prompt или пороги по результатам heldout, выдавая затем тот же набор за новую независимую проверку.

## 3. Разобрать ошибки Judge

В сохранённом пилоте 21–23.10.2026 (локальный материал: `verification/qa-step-08-2026-10-21/summary.md`) Judge дал **11 валидных оценок из 20**, 6 ответов с ошибочными цитатами и 3 усечения на лимите 512 токенов. Итог — `FAIL`. Последний случай выполнен отдельно после обновления Ollama 0.40.7 → 0.40.8; свод явно разделяет версии и не считается однородной серией. Это готовый учебный пример разбора ошибок самого оценщика. Человеческая калибровка отложена по вашему решению.

Откройте `result.json` и конкретные файлы `cases/J-001.json` и далее.

| Что смотреть | Как понимать |
|---|---|
| `summary.execution_status` | Завершены ли все наблюдения и прошли ли ответы проверку формата и ссылок. |
| `summary.known_challenge_status` | Совпали ли оценки с заранее заданными ожиданиями по дефектам и порядку. |
| `summary.overall.false_pass_rate` | Judge пропустил известный дефект: ожидалось `fail`, получено `pass`. |
| `summary.overall.false_alarm_rate` | Judge назвал ошибочным вариант, который должен пройти заданную проверку. |
| `abstain` | Модель отказалась от оценки из-за недостатка оснований. Это отдельный исход, не успешное обнаружение дефекта. |
| `invalid_response` | Неверный JSON, чужая ссылка, неточная цитата или нарушение другого правила контракта. Это ошибка ответа, а не содержательная оценка `fail`. |
| `summary.counterbalanced` | Сохранилось ли предпочтение того же содержимого после перестановки A/B; один эксперимент не доказывает отсутствие позиционного смещения. |
| `summary.human_calibration` | Покрытие настоящими человеческими оценками и согласие на сопоставимых ответах. Без оценок человека — `INCOMPLETE`. |

Знаменатели метрик сохранены явно; пропуски, ошибки и таймауты не исчезают из общего плана. `programmatic_gate` показывает отдельную проверку фактов кодом: намеренно испорченный отчёт может иметь `FAIL`, который Judge не вправе отменить.

В файле кейса `transport` содержит запрос, статус HTTP, прочитанные байты ответа, base64, SHA-256 и время. Ответы с ошибочным HTTP-статусом или недопустимыми заголовками отвергаются до чтения тела, поэтому body у них может быть пустым. `run.json` хранит стартовый протокол; итоговый статус находится в `result.json`. Файлы `ollama-before.json`, `ollama-after.json` и `source-hashes*.json` позволяют проверить идентичность модели и исходных файлов.

Коды завершения: **0 / PASS** — полная предусмотренная проверка выполнена; **1 / FAIL** — выявлено нарушение; **3 / INCOMPLETE** — не хватает обязательных наблюдений или человеческих оценок. Поэтому машинная серия без ошибок, но без заполненной человеческой формы остаётся INCOMPLETE; при ошибках сохраняется FAIL. `QA_JUDGE_INVALID_ENVELOPE` с `done_reason=length` и `eval_count=512` означает усечение, а не таймаут: посмотрите исходное тело `transport.response_body`. При ранней ошибке до создания `result.json` сохраните текст терминала: отсутствие результата не является PASS.

## 4. Сопоставить сохранённые ответы со своей оценкой

После заполнения формы сравните её с уже выполненной серией. Эта команда не вызывает модель повторно:

```powershell
& .\.venv\Scripts\python.exe -I -B .\qa\tools\score_judge.py --run-dir var/qa/judge/my-first-run --human-reviews var/qa/judge/my-materials/human-review-filled.json --output-dir var/qa/judge/my-comparison
$LASTEXITCODE
```

Каталог сравнения тоже должен быть новым. Сначала проверьте покрытие оценками, затем согласие и каждое расхождение. `EVIDENCE_COMPLETE` означает наличие сопоставимых оценок для всего плана, а не доказанную пригодность Judge. Cohen’s kappa описывает согласие вердиктов; при недостаточных или постоянных метках она может быть не определена. Даже полное согласие на этом небольшом наборе не подтверждает качество на новых банковских данных.

Judge остаётся отдельным учебным помощником: он не записывает решение оператора, не заменяет обязательные проверки и не измеряет принятие отчётов **M-08**. Используется та же модель, что у генератора, поэтому независимость её ошибок не предполагается. Проверка перестановкой A/B и сопоставление с человеком помогают изучать ограничения модельных судей, описанные в [исследовании MT-Bench](https://arxiv.org/abs/2306.05685). Продуктовая и экспертная приёмка остаются отдельными задачами.

## 5. Новый профиль compact-v2 (25.10.2026)

Полный запуск 25.10: **19/20** допустимых ответов, **16/20** совпадений с учебными метками, без усечения. Одна ошибка цитаты и три ложных одобрения сохраняют итог **FAIL**. Подробный результат (локальный материал: `verification/qa-judge-v2-2026-10-25/summary.md`) отделяет проверку кода от качества модели; независимой человеческой калибровки ещё нет.

Для учебной регрессии известных ошибок добавлен отдельный профиль. Он ограничивает ответ двумя ссылками, буквальной цитатой до 160 символов и объяснением до 300 символов; лимит вывода — 1024 токена. Динамическая схема перечисляет допустимые ref_id данного случая. Полные источники и рубрика 1.0 сохранены. Без `--profile` используется прежний `legacy-v1` с лимитом 512 токенов.

```powershell
# Терминал открыт в корне вашей копии проекта.
$qaCompactRun = 'var/qa/judge/compact-' + [guid]::NewGuid().ToString('N')
& .\.venv\Scripts\python.exe -I -B .\qa\tools\run_judge.py --profile compact-v2 --output-dir $qaCompactRun
$qaCompactExit = $LASTEXITCODE
Get-Content -LiteralPath "$qaCompactRun/result.json" -Raw
$qaCompactExit
```

Это запускает 20 новых запросов к локальной модели. Для разбора собранных ответов используйте каталог `verification/qa-judge-v2-2026-10-25/live-restart`; итог запуска находится в `result.json`. Прерванный `live-first` сохранён отдельно. Протокол измерения (локальный материал: `verification/qa-judge-v2-2026-10-25/protocol.md`) и учёт прерывания (локальный материал: `verification/qa-judge-v2-2026-10-25/recovery.json`) фиксируют бюджет и ограничения сравнения. Все эти случаи уже использовались при разработке: прежнее поле `heldout` сохранено для совместимости, но не означает новую независимую выборку.

Дополнительно сохраняются `identities/J-xxx.before.json` и журнал `attempts/*.started.json` / `*.completed.json`. Маркер начала без завершения означает возможный незавершённый запрос; он не доказывает отсутствие вызова модели. При прерывании сохраните весь каталог. Проверка не объединяет несовместимые версии автоматически и не повторяет ошибки до удачного ответа.

После независимой разметки человеком команда `score_judge.py` из раздела 4 поддерживает оба профиля. В `--run-dir` укажите выбранный сохранённый запуск compact-v2, а в `--output-dir` — новый каталог сравнения. Сначала проверяются сырые ответы, параметры, рубрика, журнал и идентичность модели. Человеческую форму по-прежнему заполняет человек до просмотра оценок модели и эталонов.

# Проверка поиска и преобразований данных

Основная установка и полный рабочий цикл собраны в [единой инструкции](service-and-lab.md). Команды этого справочника выполняются из корня вашей копии. Упоминания сохранённых прогонов относятся к указанной дате; их локальные архивы не входят в обычный клон.

Инструкция для **PowerShell в терминале VS Code**, актуальна на **20.10.2026**. Шаг 6 завершён: в прогоне 19.10 выполнены 13 случаев поиска и 5/5 семейств преобразований; итоговая квалификация — **15/15 PASS**. Отчёт и сохранённые свидетельства (локальный материал: `verification/qa-step-06-2026-10-19/summary.md`).

Скрипт использует сохранённую модель поиска на CPU и формирует отчёты по шаблону `template`. Он проверяет, какие фрагменты находятся по запросу и как результат меняется при заданных изменениях входных данных. Запускать API, UI, PostgreSQL, Kafka или Docker для этого упражнения не нужно. Генерация Ollama и LLM Judge в этот набор не входят.

## 1. Проверить подготовку

Используйте существующее окружение проекта `.venv`. Модель `paraphrase-multilingual-MiniLM-L12-v2` должна уже находиться в `var/models` вместе с файлом манифеста. Скрипт проверяет целостность модели и работает без скачивания; сетевые соединения Python запрещены на время проверки.

```powershell
# Терминал открыт в корне вашей копии проекта.
Test-Path -LiteralPath '.venv\Scripts\python.exe'
Test-Path -LiteralPath 'var\models\paraphrase-multilingual-MiniLM-L12-v2'
Test-Path -LiteralPath 'var\models\paraphrase-multilingual-MiniLM-L12-v2.manifest.json'
```

Все три команды должны вернуть `True`. Это проверка наличия; хеши и содержимое проверит сам запуск. Если файла нет, сначала восстановите подготовку окружения проекта. Не подставляйте другую модель и не исправляйте манифест вручную ради успешного результата.

## 2. Выполнить проверку

Каталог результата должен быть **новым**. Для первого запуска:

```powershell
$qaEvidence = 'var/qa/retrieval/my-first-run'
& .\.venv\Scripts\python.exe -I -B .\qa\tools\run_retrieval.py --output-dir $qaEvidence
$qaExitCode = $LASTEXITCODE
if (Test-Path -LiteralPath (Join-Path $qaEvidence 'result.json')) {
    Get-Content -LiteralPath (Join-Path $qaEvidence 'result.json') -Raw
}
$qaExitCode
```

Загрузка модели может занять время. Во время прогона не редактируйте исходный код, тестовый набор или файлы модели: скрипт сверяет хеши до и после выполнения. Он создаёт копии синтетических источников внутри каталога результата; замороженные эталоны не перезаписываются.

Для повтора задайте новое имя, затем выполните ту же команду запуска:

```powershell
$qaEvidence = 'var/qa/retrieval/run-' + [guid]::NewGuid().ToString('N')
```

`QA_EVIDENCE_ALREADY_EXISTS` означает, что выбранный каталог уже существует. Сохраните прежний результат и выберите новое имя.

## 3. Прочитать результат

| Файл относительно `$qaEvidence` | Что смотреть |
|---|---|
| `result.json` | Итоговый `status`, число проверок, `source_files_unchanged_during_run`, время и границы проверки. |
| `ranking/result.json` | Метрики пяти основных запросов в `primary_macro`; остальные случаи и связи между ними показаны отдельно. |
| `ranking/R01.json` … `ranking/R13.json` | Текст запроса, дата, релевантные цитаты, полная выдача `ranked`, расстояния и метрики конкретного случая. |
| `ranking/index-base.json`, `ranking/index-editions.json` | Реально построенные фрагменты, их тексты, границы, версии и происхождение индекса. |
| `metamorphic/summary.json` | Итоги пяти семейств преобразований; ожидаются 10 наблюдений — до и после каждого изменения. |
| `metamorphic/MT-01/` … `metamorphic/MT-05/` | Исходные копии `before/`, `after/`, наблюдения `before-observation.json`, `after-observation.json`, хеши в `inputs.json` и итог в `result.json`. |
| `runtime.json`, `embedding-calls.json` | Модель, версии библиотек, CPU, параметры исполнения и измеренное время вызовов. |
| `source-hashes.json` | Хеши кода, зависимостей и манифестов, с которыми получен результат. |

Код выхода `0` и `status: PASS` означают, что измерения корректно выполнены и заданные отношения прошли проверку. Ожидаемый состав — **13 случаев поиска и 5 семейств преобразований**, без изменения исходных файлов во время прогона. `FAIL` / код `1` означает нарушение проверяемого отношения; `ERROR` / код `2` — ошибку выполнения или целостности. При ошибке подготовки каталог результата может ещё не появиться: сохраните сообщение из терминала.

**Технический PASS не является приёмкой качества модели.** Поле `ranking_quality_acceptance` остаётся `NOT_ESTABLISHED`, а `product_acceptance` — `INCOMPLETE`. Для приёмки нужны отдельные критерии и оценка на подходящих данных. Этот набор не подтверждает M-07, юридическую применимость правил или экспертное принятие отчёта.

## 4. Разобрать качество поиска

Основное среднее считается только по **R01–R05**: пяти положительным темам запросов на небольшом синтетическом корпусе. Остальные **8 случаев диагностические**: алиасы, даты редакций и отрицательные контроли. Они не увеличивают знаменатель среднего. Набор открыт и не является независимой отложенной выборкой; подробности разметки — в [описании набора](../../qa/datasets/retrieval-v1/README.md).

| Метрика | Как прочитать |
|---|---|
| `precision_at_k` — P@1 / P@3 | Число релевантных фрагментов в первых `k`, делённое на `k`. Знаменатель не уменьшается, если выдача короче. |
| `recall_at_k` — R@1 / R@3 | Доля всех размеченных релевантных фрагментов, найденных в первых `k`. |
| `mrr_full` | Среднее `1 / позиция первого релевантного фрагмента` по полной выдаче пяти основных запросов. Не путайте с `reciprocal_rank_at_k`, ограниченным первыми `k`. |

Совпадение проверяется по полной идентичности цитаты: правило, редакция, ссылка на источник, фрагмент и хеш текста. Например, при единственном релевантном фрагменте на первой позиции P@1 = 1, R@1 = 1, а **максимальное P@3 = 1/3**, даже при отличном результате этого запроса. Поэтому произвольный порог «P@3 должно быть 1» здесь неверен.

Если релевантных фрагментов в разметке нет, P@k, R@k и обратный ранг записываются как `null`; такой случай исключён из среднего. Для `velocity` нет прямого соответствия в корпусе, но поиск может вернуть ближайшие фрагменты: **порог отказа в поиске не реализован**. Это отличается от R13, где на выбранную дату нет действующих редакций и выдача должна быть пустой.

В сохранённом прогоне 19.10 целевой фрагмент найден первым в **4 из 5** основных запросов; R@3 = **1**, P@3 = **1/3**, MRR = **0,866667**. Для `threshold` целевой `R-115-006` стоит третьим. Изучите R02 (локальный материал: `verification/qa-step-06-2026-10-19/model-final/ranking/R02.json`), чтобы увидеть, почему технический PASS не означает идеальное ранжирование. Runtime получает все действующие фрагменты, затем фильтрует их по политике; третье место здесь само по себе не доказывает потерю правила в готовом отчёте.

Время в результатах — наблюдение на вашей машине с текущей нагрузкой, а не подтверждённый SLA. Сравнивайте повторные прогоны с учётом модели, библиотек, CPU и исходных хешей.

## 5. Разобрать преобразования данных

Метаморфная проверка задаёт изменение входа и ожидаемую связь между результатами. Здесь используются настоящий сбор контекста, поиск и шаблон отчёта; у каждого результата дополнительно проверяются факты, источники и контракт.

| Случай | Изменение → ожидаемый результат |
|---|---|
| `MT-01` | Перестановка строк источников → смысл контекста, факты и цитаты сохраняются. |
| `MT-02` | Те же моменты времени представлены в UTC−04:00 → состав операций в окне, факты и цитаты сохраняются. |
| `MT-03` | Сумма `TX-7700` увеличена ровно на `0.01` → изменяются только факт этой операции и итог RUB, также ровно на `0.01`. |
| `MT-04` | Удалена единственная операция выбранного клиента → вместо черновика возвращается `INSUFFICIENT_DATA` до вызова поиска. |
| `MT-05` | Перейдена граница действия редакций → `R-115-006` меняет `2024-rev3` на `qa-2026-rev1` ровно в установленный момент. |

Для первой практики откройте `metamorphic/MT-03/before/transactions.json` и `after/transactions.json`, затем сравните `found_facts` в двух файлах наблюдений. В `inputs.json` видны изменённые файлы и хеши, в `result.json` — обнаруженные нарушения. Это пять заданных семейств, а не статистическая оценка всех возможных данных.

Для разбора поиска сравните `ranking/R01.json` с его метриками и полными цитатами, затем изучите случай `velocity`. Не меняйте замороженную разметку под полученную выдачу: новая постановка эксперимента требует отдельной версии набора. Результаты самостоятельных запусков сохраняйте в новых каталогах для сравнения.

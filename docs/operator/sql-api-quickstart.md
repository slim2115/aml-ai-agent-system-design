# Учебная БД и Swagger: инструкция

Основная установка и полный рабочий цикл собраны в [единой инструкции](service-and-lab.md). Команды этого справочника выполняются из корня вашей копии. Упоминания сохранённых прогонов относятся к указанной дате; их локальные архивы не входят в обычный клон.

Актуально на 20.10.2026. Для SQL доступен **DBeaver с графическим интерфейсом**, для API — Swagger в браузере. [Инструкция DBeaver: запуск ярлыком, подключение и первый запрос](dbeaver-quickstart.md). Для самостоятельной практики ниже AML-интерфейс и модели не требуются; `psql` остаётся резервным клиентом.

**Общий маршрут занятия:** [SQL, API и Kafka: полный учебный цикл](integration-practice.md) — схема архитектуры, запуск, примеры запросов и разбор результатов (04.10.2026).

**Дополнительный маршрут:** [Kafka → AML-анализ → пошаговая проверка](kafka-aml-quickstart.md). Новые `/lab/kafka/analyses` и `Run-AmlWorker.ps1` связывают событие с AML-заданием; `Start-IntegratedUI.ps1` использует общую историю API `var/workflow/api-workflow.sqlite3`. В SQL можно читать его проекцию из `kafka_lab.analysis_requests`, но данные `practice` по-прежнему не являются источниками AML-анализа.

## 1. Запустить из VS Code

Без терминала: откройте `lab\desktop\AML SQL API - Start.lnk` из Проводника. Он запускает те же PostgreSQL/API и открывает DBeaver. Дальнейшие команды — альтернативный способ запуска.

Откройте папку `.`, затем **Терминал → Создать терминал**. Обычный запуск `Start-Lab.ps1` поддерживает Windows PowerShell 5.1 и PowerShell 7. Для установки и расширенных проверок используйте PowerShell 7; перейти в имеющуюся версию можно командой:

```powershell
pwsh -NoLogo
```

Запустите стенд:

```powershell
# Терминал открыт в корне вашей копии проекта.
.\scripts\lab\Start-Lab.ps1
```

После сообщения с адресом Swagger откройте **[http://127.0.0.1:8765/docs](http://127.0.0.1:8765/docs)**. Серверы работают в отдельных фоновых процессах, терминал сразу готов к следующим командам. Повторный запуск не сбрасывает данные. После перезагрузки компьютера выполните запуск снова. Для штатной остановки используйте `Stop-Lab.ps1` из раздела 4.

## 2. Отправить первый API-запрос

Без терминала откройте `var/postgres/lab-connection.json` в VS Code и скопируйте только значение `api_token` без кавычек. Не публикуйте этот файл. Альтернатива — скопировать ключ командой:

```powershell
$labAccess = Get-Content .\var\postgres\lab-connection.json -Raw | ConvertFrom-Json
$labAccess.api_token | Set-Clipboard
```

1. В Swagger нажмите **Authorize**, вставьте ключ в **Value**, нажмите **Authorize**, затем **Close**. Вставляется только значение ключа, без слова `Bearer`.
2. Раскройте **GET /lab/clients** → **Try it out** → **Execute**.
3. В разделе **Server response** ожидается код **200**, в **Response body** — список клиентов. После перезагрузки страницы авторизуйтесь снова.

Для заметки раскройте **POST /lab/notes**, нажмите **Try it out** и отправьте:

```json
{"incident_id":"INC-000123","body":"Моя первая учебная заметка"}
```

Ответ **201** содержит `id` и `revision: 1`. Сохраните `id`: он нужен для чтения, изменения и удаления этой заметки.

- **GET /lab/notes/{note_id}**: подставьте `id`, чтобы прочитать заметку.
- **PATCH /lab/notes/{note_id}**: отправьте `{"body":"Обновлённый текст","expected_revision":1}`. Успех — **200**, новая ревизия — `2`.
- **DELETE /lab/notes/{note_id}**: укажите актуальную `expected_revision=2`. Успех — **204**, тело ответа пустое.

**401** — отсутствует или неверен ключ. **409** — версия уже изменилась: прочитайте заметку заново. **400** — проверьте поля запроса. Для упражнений с учебными таблицами используйте группу `/lab`; `/v1` управляет AML-заданиями и обслуживает также интегрированный UI.

## 3. Выполнить первый SQL-запрос

В DBeaver выберите **AML — практика → SQL Editor → New SQL Script** и выполните SQL ниже через **Ctrl+Enter**. Для применения изменений используйте Commit, для отмены — Rollback.

Если предпочитаете резервный `psql`, откройте его в PowerShell:

```powershell
.\scripts\lab\Open-Sql.ps1
```

После появления приглашения `aml_lab=>` введите SQL с точкой с запятой:

```sql
SELECT * FROM practice.clients;
SELECT id, incident_id, body, revision FROM practice.case_notes;
```

Вторая команда показывает те же заметки, с которыми работает Swagger. Если заметка удалена на предыдущем шаге, её уже не будет. Для выхода из `psql` в PowerShell введите **`\q`**. Если вывод открылся постранично с надписью `(END)`, сначала нажмите **q**.

Параметры для подключения другим SQL-клиентом: сервер `127.0.0.1`, порт `55432`, база `aml_lab`, пользователь `aml_student`; пароль — поле `roles.student.password` в локальном файле `var/postgres/lab-connection.json`.

**`practice`** — данные для изменений; **`reference`** — исходный набор для сравнения. SQL/API-изменения не меняют зафиксированные данные, которые анализирует AML-сервис. Заметки не являются решениями оператора по отчёту.

## 4. Остановить или восстановить стенд

В DBeaver завершите транзакции через Commit/Rollback, отключите соединения и откройте `lab\desktop\AML SQL API - Stop.lnk`. Альтернатива: выйдите из `psql` через `\q` и остановите серверы из PowerShell:

```powershell
.\scripts\lab\Stop-Lab.ps1
```

Данные сохранятся. Закрытие Swagger или терминала не заменяет эту команду. Если запущен интегрированный AML-режим, сначала завершите задания и остановите его обработчик по [инструкции интеграции](kafka-aml-quickstart.md): остановка API затрагивает выполняющийся анализ.

Если нужно начать упражнения с исходного набора, запустите стенд, завершите работу с запросами и выполните **явный сброс**:

```powershell
.\.venv\Scripts\python.exe -I -B scripts\lab\database.py reset-practice --confirm-practice-reset
```

Команда удаляет ваши изменения, заметки и созданные объекты в `practice`. `reference` и результаты AML-сервиса сохраняются. Для обычного запуска сброс не нужен.

Если браузер не открывается, проверьте сообщение команды запуска и адрес с портом **8765**. Если API выдаёт **503**, повторите `Start-Lab.ps1` и проверьте **GET /lab/status**. Ошибки запуска записываются в `var/logs/lab-api.err.log` и `var/logs/postgres-lab.log`.

В обновлённом `Start-Lab.ps1` устранён ложный таймаут `API did not start` в Windows PowerShell 5.1: проверка доступности больше не использует неподдерживаемый параметр `-NoProxy`. Если появляется новая ошибка запуска, строка `Last readiness check` показывает причину последней неудачной проверки; при завершении процесса выводится код выхода. `/health` подтверждает работу HTTP-сервера, а доступность PostgreSQL скрипт проверяет отдельно перед запуском API.

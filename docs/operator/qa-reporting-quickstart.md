# Общий QA-отчёт и профили CI

Основная установка и полный рабочий цикл собраны в [единой инструкции](service-and-lab.md). Команды этого справочника выполняются из корня вашей копии. Упоминания сохранённых прогонов относятся к указанной дате; их локальные архивы не входят в обычный клон.

Рабочая папка: `.`. Команды ниже выполняются в терминале VS Code, PowerShell 7. Каждый результат сохраняйте в **новую папку**.

## Посмотреть уже собранные результаты

Обновление 25.10: новый QA-отчёт (локальный материал: `verification/qa-judge-v2-2026-10-25/current-report/report.html`) включает текущую регрессию и отдельную полную серию Judge compact-v2. Остальные профили взяты из сохранённых исторических измерений; это не новый сквозной запуск всех сервисов. Judge сохраняет FAIL (19/20 допустимых ответов, 16/20 совпадений), человеческая калибровка — INCOMPLETE. Старый отчёт ниже сохранён для сравнения.

Откройте HTML-отчёт (локальный материал: `verification/qa-step-09-2026-10-23/report-qualified/report.html`) в браузере. Рядом находятся краткая сводка (локальный материал: `verification/qa-step-09-2026-10-23/report-qualified/summary.md`), JSON с версиями и связями (локальный материал: `verification/qa-step-09-2026-10-23/report-qualified/report.json`) и индекс входных файлов с SHA-256 (локальный материал: `verification/qa-step-09-2026-10-23/historical-index.json`).

Это свод сохранённых измерений разных дней. Он не запускает сервис и не доказывает, что все компоненты сейчас работают одновременно. Общий `FAIL` ожидаем: Judge шага 8 дал 11 допустимых ответов из 20. Успешные программные тесты сохраняют свой отдельный `PASS`. Человеческая калибровка остаётся `INCOMPLETE`, она отложена по вашему решению.

Собрать такой же отчёт в новую папку без моделей, API или Kafka:

```powershell
# Терминал открыт в корне вашей копии проекта.
& .\.venv\Scripts\python.exe -I -B qa/tools/build_qa_report.py --index verification/qa-step-09-2026-10-23/historical-index.json --output-dir var/qa/reports/my-history-01
$LASTEXITCODE
```

Откройте `var/qa/reports/my-history-01/report.html` через проводник или браузер. Код **1** здесь означает сохранённый отрицательный итог Judge. Проверка изменения входного файла по SHA-256 также приводит к неуспешному результату; переименованием файла это не исправить.

## Выбрать проверку

| Профиль | Когда нужен | Инструкция |
|---|---|---|
| Изолированный CI | Проверка кода, контрактов, AppTest; без реальных моделей и брокера | Команда ниже, [описание CI](../rebuild/ci-cd.md) |
| Browser smoke | Один сценарий создания задания и проверки источников в настоящем Chromium | Команды ниже |
| Полный browser | Все 12 детерминированных сценариев, trace и контрольный дефект | [Playwright](qa-playwright-quickstart.md) |
| Live integration | Реальная цепочка SQL/API/Kafka → AML → UI и сбои | [Практикум цепочки](qa-pipeline-quickstart.md) |
| Model evaluation | Отдельно качество поиска и повторные генерации | [Поиск](qa-retrieval-quickstart.md), [LLM](qa-llm-quickstart.md) |
| Judge | Проверка модельного оценщика и сопоставление с независимой разметкой | [Judge](qa-judge-quickstart.md) |

Тяжёлые профили запускаются явно локально. Автоматических запусков моделей, новых runner или расписаний нет.

## Чистый локальный CI

```powershell
& .\scripts\ci\Test-Ci.ps1
```

Скрипт создаёт отдельное окружение из уже скачанных пакетов, проверяет точные версии, запускает полный pytest и Streamlit AppTest. Рабочая `.venv` сохраняется. В конце он выводит папку `var/checks/ci-local/<идентификатор>`.

Подставьте показанный идентификатор и создайте отчёт:

```powershell
& .\.venv\Scripts\python.exe -I -B qa/tools/report_ci.py --profile hermetic --input-dir var/checks/ci-local/ВАШ_ИДЕНТИФИКАТОР --output-dir var/checks/my-ci-report-01
```

Если установка или один из этапов не состоялся, отчёт покажет отсутствие свидетельств. Нельзя заменять отсутствующий этап результатом старого прогона. Основные pytest-тесты и дополнительные subtests отображаются отдельно: успешные subtests могут присутствовать только в счётчике JUnit, без отдельных XML-узлов.

## Один браузерный smoke

На подготовленной машине с установленными [инструментами Playwright](qa-playwright-quickstart.md) и свободными QA-портами 18501/18765:

```powershell
& .\.venv\Scripts\python.exe -I -B qa/tools/run_ci_browser.py --output-dir var/qa/ci-browser-manual-01
& .\.venv\Scripts\python.exe -I -B qa/tools/report_ci.py --profile browser --input-dir var/qa/ci-browser-manual-01 --output-dir var/checks/browser-report-manual-01
```

Профиль сам создаёт отдельные данные, запускает UI/API, выполняет один тест в Chromium и останавливает свои службы. `cleanup_status=PASS` подтверждает остановку. При принудительном завершении терминала очистка может не выполниться: сначала проверьте свой QA-профиль по инструкции стенда. Трассы и журналы остаются внутри принадлежащего прогону каталога; в CI публикуется только очищенный отчёт.

## Найти связь между событием и отчётом

В `report.json` откройте `correlation_rows`. Ключ наблюдения — путь исходного свидетельства вместе с `case_id` и `repetition`. Имена кейсов и даже `run_id` могут повторяться в разных прогонах.

- У pipeline `QA-P01` доступны Kafka `topic/partition/offset`, `event_id`, `job_id`, `report_id`, версия и хеш отчёта, идентификаторы открытых в UI задания и отчёта.
- У poison message могут отсутствовать event/job/report: это ожидаемый отказ до создания задания.
- У LLM есть сценарий, повтор и отчёт, но нет операционного Kafka-события.
- Judge связан с исходным повтором LLM через путь и SHA-256. Изменённые кандидаты могут сохранять исходный `report_id`, поэтому одного этого поля недостаточно для связи.
- `null` означает отсутствие свидетельства. Трасса успешного браузерного теста обычно отсутствует, поскольку действует политика сохранения при сбое.

## Что появится после вашего push

[Workflow](../../.github/workflows/ci.yml) содержит независимые задания `hermetic-windows` и `browser-smoke-windows`. Каждое создаёт своё резюме GitHub Actions и артефакт очищенного отчёта. Отправку изменений и запуск удалённого CI подтверждает владелец проекта; локальный PASS не заменяет успешный Actions run на конкретном commit SHA.

`report_ci.py` возвращает **0 — PASS**, **1 — FAIL/ERROR**, **3 — INCOMPLETE**. `product_acceptance=INCOMPLETE` сохраняется отдельно от статуса технического профиля. Подробные условия установки, публикации и очистки — в [описании профилей CI](../rebuild/qa-ci-profiles.md).

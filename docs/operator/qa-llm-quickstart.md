# Повторные прогоны настоящей LLM

Основная установка и полный рабочий цикл собраны в [единой инструкции](service-and-lab.md). Команды этого справочника выполняются из корня вашей копии. Упоминания сохранённых прогонов относятся к указанной дате; их локальные архивы не входят в обычный клон.

Инструкция для PowerShell в терминале VS Code, **21.10.2026**. Это шаг 7 [плана QA](../rebuild/qa-practice-plan.md): проверка фактов и вариативности на синтетических сценариях. Инструкция описывает запуск; результаты конкретного прогона смотрите в его сохранённых артефактах.

В сохранённой серии от 20.10 (локальный материал: `verification/qa-step-07-2026-10-20/summary.md`) прошли 15/15 генераций и 8/8 контролей. Все первые ответы валидны, исправляющих повторов нет; факты и порядок совпали с шаблоном. Первый вызов занял 62,03 с, остальные — 6,66–16,13 с; отдельная подготовка поиска — 141,56 с. Это ориентиры этой серии на данном компьютере, а не гарантированные сроки. Полезность модельного порядка ещё предстоит оценить.

В нашем сервисе LLM выбирает **порядок уже подготовленных идентификаторов фактов и правил**. Суммы, тексты фактов, состав операций и ссылки на источники вычисляет код. Поэтому допустим разный порядок, но недопустимы пропущенный факт, выдуманная сумма, дубликат или неверная редакция правила. Это проверка ограниченной задачи модели, а не качества свободного аналитического заключения.

## 1. Проверить подготовку

Нужны существующее окружение `.venv`, сохранённая модель поиска `paraphrase-multilingual-MiniLM-L12-v2` с манифестом и локальный Ollama с уже установленной `qwen2.5:14b`. Запустите установленное приложение Ollama. API сервиса, браузер, PostgreSQL и Kafka для этого упражнения не требуются.

```powershell
# Терминал открыт в корне вашей копии проекта.
Test-Path -LiteralPath '.venv\Scripts\python.exe'
Test-Path -LiteralPath 'var\models\paraphrase-multilingual-MiniLM-L12-v2'
Test-Path -LiteralPath 'var\models\paraphrase-multilingual-MiniLM-L12-v2.manifest.json'
ollama list
Invoke-RestMethod -Uri 'http://127.0.0.1:11434/api/ps'
```

Три `Test-Path` должны вернуть `True`; в `ollama list` должна быть `qwen2.5:14b`. Скрипт дополнительно сверяет полный digest подготовленной версии: одного совпадения имени недостаточно. `/api/ps` показывает модели, загруженные в память: пустой список сам по себе не означает, что модель не установлена. [Описание `/api/ps`](https://docs.ollama.com/api/ps).

Скрипт использует существующую модель поиска без скачивания, читает исходные модели и эталоны, а результаты сохраняет отдельно. Вызовы генерации идут только в локальный Ollama. Не меняйте файлы модели, сценарии и код во время измерения; другие задания с LLM лучше завершить заранее, чтобы они не влияли на время отклика. Новую модель этот запуск не устанавливает.

## 2. Запустить серию

Выберите **новый** каталог результата:

```powershell
$qaEvidence = 'var/qa/llm/my-first-run'
& .\.venv\Scripts\python.exe -I -B .\qa\tools\run_llm.py --output-dir $qaEvidence --repeats 3
$qaExitCode = $LASTEXITCODE
if (Test-Path -LiteralPath (Join-Path $qaEvidence 'result.json')) {
    Get-Content -LiteralPath (Join-Path $qaEvidence 'result.json') -Raw
}
$qaExitCode
```

Для следующей серии измените имя и повторите команду:

```powershell
$qaEvidence = 'var/qa/llm/run-' + [guid]::NewGuid().ToString('N')
```

Повтор не должен перезаписывать прежнее свидетельство, в том числе неуспешное.

Состав серии:

| Сценарии | Сколько запусков | Что проверяется |
|---|---:|---|
| `QA-S01`, `QA-S02`, `QA-S03`, `QA-S04`, `QA-S14` | По 3, всего 15 | Настоящие поиск и LLM, полный состав фактов, суммы, источники, редакции правил и порядок ответов. |
| `QA-S05`–`QA-S12` | По 1, всего 8 | Ошибки входа и отказы; вызов LLM для этих контролей не требуется. |
| `QA-S13`, `QA-S15` | Исключены | Эти сценарии задают недоступный или неверно отвечающий тестовый transport; их подмены не считаются настоящей LLM. |

Это **5 сценариев с генерацией и 8 контролей**, а не 23 независимых примера качества модели. Повторения измеряют устойчивость на тех же входах. Если после неверного ответа runtime повторит запрос, такая попытка тоже должна остаться в свидетельствах; число HTTP-вызовов не обязано совпадать с числом запусков сценариев.

Сохраняется рабочий режим генерации: `qwen2.5:14b`, `temperature=0`, структурированный JSON. Температура 0 не заменяет измерение повторяемости: проверьте фактические ответы, а не ожидайте обязательного совпадения. Формат запроса и поля времени описаны в [документации Ollama `/api/chat`](https://docs.ollama.com/api/chat).

## 3. Прочитать результат

Первым откройте `result.json` в каталоге запуска. Не ограничивайтесь последней строкой терминала: сверьте состав выполненных сценариев, сохранённые попытки и причину каждого неуспеха.

| Файл относительно `$qaEvidence` | Что смотреть |
|---|---|
| `result.json` | Итоговый `status`, `summary`, восемь `controls`, числа наблюдений, полнота матрицы и неизменность исходных файлов. В `raw_attempt_summary` отдельно видны правильность первых ответов и повторные попытки исправления. |
| `run.json` | Запланированные кейсы, число повторов, модель, digest и параметры. Его начальный `status: INCOMPLETE` обозначает стартовый протокол; итог находится в `result.json`. |
| `cases/QA-S01/template.json` | Контрольный отчёт `template` на тех же данных, выдача поиска и результаты проверки. Аналогичные файлы есть у остальных кейсов. |
| `cases/QA-S01/repeat-01.json` … `repeat-03.json` | `evaluation`, готовый отчёт в `observation.result`, контекст, модельные запросы, события и выдача `rankings`. |
| `http_attempts` внутри каждого повтора | Точное тело HTTP-запроса и ответа, хеш ответа, длительность, статус HTTP. Здесь сохраняются и неуспешные попытки. |
| `ollama-before.json`, `ollama-after.json` | Версия сервера, идентичность модели, её параметры и список загруженных моделей до и после серии. |
| `runtime.json`, `embedding-calls.json` | Версии библиотек, CPU, время загрузки поиска, дедлайн генерации и вызовы embedding. |
| `source-hashes.json`, `source-hashes-after.json` | Хеши кода и манифестов для проверки неизменности. |

- **PASS / код выхода 0**: все обязательные проверки полной матрицы выполнены и прошли.
- **FAIL / код 1**: измеренная проверка нарушена. Успешный повтор не удаляет предыдущую ошибку.
- **INCOMPLETE / код 3**: не хватает зависимости или обязательного свидетельства либо выполнен сокращённый запуск, например с `--case-id QA-S01` или менее чем тремя повторами. Это не успешная проверка полного шага.

При ошибке сбора смотрите `error_code` и `error_type`. Если запуск остановился до создания `result.json`, сохраните сообщение и код выхода: такая ранняя ошибка может иметь другой код. Отсутствие артефакта нельзя трактовать как PASS.

## 4. Первое упражнение: факты и порядок

Начните с `QA-S01`: ожидаются **12 операций по 95000.00 RUB**, итог **1140000.00 RUB** и **17 фактов**. После завершения серии выведите краткое сравнение:

```powershell
Get-ChildItem -LiteralPath (Join-Path $qaEvidence 'cases/QA-S01') -Filter 'repeat-*.json' |
    Sort-Object Name |
    ForEach-Object {
        $qaRepeat = Get-Content -LiteralPath $_.FullName -Raw | ConvertFrom-Json
        [pscustomobject]@{
            File = $_.Name
            Status = $qaRepeat.evaluation.status
            Facts = @($qaRepeat.observation.result.found_facts).Count
            ModelCalls = @($qaRepeat.http_attempts).Count
            ModelState = $qaRepeat.model_load_state
            Seconds = $qaRepeat.observation.latency_seconds
        }
    } | Format-Table -AutoSize
```

Затем откройте первый ответ и готовые факты:

```powershell
$qaRepeat = Get-Content -LiteralPath (Join-Path $qaEvidence 'cases/QA-S01/repeat-01.json') -Raw | ConvertFrom-Json
$qaRepeat.http_attempts | ForEach-Object { $_.response_json.message.content }
$qaRepeat.observation.result.found_facts | Select-Object fact, evidence | Format-List
$qaRepeat.evaluation | ConvertTo-Json -Depth 15
```

Ответ модели — JSON с порядком идентификаторов; человекочитаемые факты находятся в готовом отчёте. Сравните три повтора:

1. В запросах должны совпадать исходный сценарий и каталог допустимых идентификаторов.
2. В ответах модели сравните `fact_order` и `rule_order`: каждый допустимый идентификатор должен встретиться ровно один раз.
3. В готовых отчётах сравните полный состав `found_facts`, значения и ссылки `evidence`, затем `applicable_rules` с версиями и хешами цитат.
4. Изменение порядка при сохранении состава — наблюдаемая вариативность. Новый факт, пропуск или изменение суммы — нарушение. Разные `report_id` и `generated_at` сами по себе не являются ошибкой.

Затем разберите `QA-S03`: **1500012.30 USD** и **100.05 RUB** должны остаться раздельными суммами; учитываются все три статуса операций. В `QA-S04` нужна редакция `R-115-006/qa-2026-rev1`. В `QA-S14` текст инструкции из назначения платежа не должен оказаться в модельном запросе или фактах. Полные ожидания и происхождение данных — в [описании набора AML v1](../../qa/datasets/aml-v1/README.md).

Не сравнивайте весь JSON побайтово: время и идентификатор отчёта меняются, а порядок как раз является предметом измерения. При сравнении разных серий сначала проверьте одинаковые версии модели, параметров, prompt и исходных файлов.

В `result.json → raw_attempt_summary` сравните `first_attempt_valid_count` с `observations`, затем посмотрите `repair_attempted_count` и `total_http_attempts`. Успешный отчёт после исправления и правильный ответ с первой попытки — разные наблюдения; все исходные ответы доступны в `http_attempts`.

## 5. Как понимать границы результата

Первый запрос может включать загрузку модели, последующие — использовать уже загруженную. Поле `model_load_state` обозначает наличие модели в `/api/ps` непосредственно перед запросом; подпись `cold` сама по себе не доказывает полное отсутствие кешей. Сверяйте её с `loaded_before` и измеренным `load_duration` ответа Ollama.

Разделяйте время загрузки, обработки запроса и генерации, если эти поля присутствуют в свидетельствах; длительности Ollama указаны в наносекундах. Время ожидания в очереди отдельно не измеряется. Один медленный ответ не объясняется автоматически моделью: на него может влиять загрузка компьютера или очередь Ollama.

Сохранение фактов подтверждает работу ограниченного контракта, но не способность LLM самостоятельно находить нарушения или делать юридические выводы. Отчёт остаётся `draft`, `suspicious_patterns=[]`, `confidence=null`; решение принимает человек.

Этот небольшой открытый синтетический набор не подтверждает производственную приёмку, нормативную актуальность или принятие отчётов AML-экспертом. **Продуктовая приёмка остаётся `INCOMPLETE`.** LLM-as-a-Judge и его калибровка — следующий отдельный этап; Judge не может отменить ошибки фактов и источников.

# AML — пошаговая проверка: инструкция оператора

Основная установка и полный рабочий цикл собраны в [единой инструкции](service-and-lab.md). Команды этого справочника выполняются из корня вашей копии. Упоминания сохранённых прогонов относятся к указанной дате; их локальные архивы не входят в обычный клон.

Актуально на 05.10.2026. Локальная версия работает на синтетических данных; решения и доставка учебные. Установка уже выполнена. Команды ниже запускают автономный режим: для него PostgreSQL и Swagger не требуются.

Для обучения SQL, API и Kafka используйте [сквозную инструкцию учебного стенда](integration-practice.md). Чтобы получать AML-задания из Kafka в этот интерфейс, выберите [интегрированный режим](kafka-aml-quickstart.md): `Start-IntegratedUI.ps1` подключает UI к общей истории API `var/workflow/api-workflow.sqlite3`, а `Run-AmlWorker.ps1` передаёт события в AML-процесс. Автономная история `var/workflow/workflow.sqlite3` сохраняется отдельно. Этапы проверки и правила решения одинаковы; на порту 8501 запускайте только один выбранный режим.

В интегрированном режиме задание из Kafka уже создано обработчиком. В боковой панели раскройте **«Запросы AML из Kafka»**, найдите свой `event_id` и нажмите **«Открыть задание из Kafka»**, когда появится `job_id`. Не нажимайте «Создать задание» для повторного открытия: эта кнопка начинает самостоятельный анализ. В автономном режиме задания из истории API не отображаются.

## 1. Запустить из VS Code

Откройте в VS Code папку `.`, затем **Терминал → Создать терминал**. Используйте PowerShell 7. Если доступен только Windows PowerShell, запустите имеющуюся на вашей машине версию 7 командой:

```powershell
pwsh -NoLogo
```

Выполните:

```powershell
# Терминал открыт в корне вашей копии проекта.
& .\scripts\rebuild\Enter-LocalEnvironment.ps1
& .\.venv\Scripts\python.exe -I -B -m streamlit run .\src\ui\app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --browser.gatherUsageStats false
```

Оставьте терминал работающим и откройте в браузере **[http://127.0.0.1:8501](http://127.0.0.1:8501)**. Должна появиться страница **«AML — пошаговая проверка»**. Активировать `.venv` отдельно не нужно. Команды подготовки выполняются заново в каждом новом терминале.

## 2. Пройти пять этапов в браузере

Переключатель **«Этап работы»** позволяет двигаться вперёд и возвращаться к источникам. Переключение этапа само по себе не сохраняет решение и не запускает экспорт.

1. **Подготовка.** Нажмите **«Подготовить поиск»**. Дождитесь сообщения о готовности; состояние обновляется автоматически. На подготовку отведено до 3 минут. Если она завершилась ошибкой, прочитайте показанную причину и следующий шаг.
2. **Инцидент.** Укажите **`INC-000123`**, включите **«Использовать учебную политику и синтетический снимок»** и оставьте **«Проверяемый шаблон (без LLM)»**. Нажмите **«Создать задание»** один раз. Состояние обработки обновляется автоматически; при необходимости нажмите **«Обновить состояние»**. Шаблон требует подготовленного поиска, но не требует Ollama.
3. **Проверка отчёта.** Сверьте факты с таблицами источников: значения, операции и период. Таблица каждого факта открывается через **«Сверить источники факта …»**. Прочитайте использованные учебные правила и их редакции. Идентификаторы, хеши и другие технические подробности находятся в раскрываемых блоках. Проверенные источники не заменяют оценку содержания отчёта оператором. После проверки нажмите **«Перейти к решению»** над отчётом.
4. **Решение.** В поле **«Решение»** сначала отображается нейтральное предложение выбрать действие. Выберите нужный вариант и заполните обязательное **«Обоснование решения»**. Основания отчёта доступны и на этом этапе в раскрываемой панели. Затем нажмите **«Сохранить учебное решение»**.
5. **Сохранение и экспорт.** Проверьте сохранённое решение. Для одобренного отчёта доступны подтверждение последствия экспорта и локальный экспорт; порядок описан ниже. Решения и операции доставки показываются отдельно: сохранение решения ещё не означает экспорт.

Дополнительный режим **«Локальная модель: порядок фактов»** требует работающего Ollama с `qwen2.5:14b` на `127.0.0.1:11434`. Сервис сам его не запускает. В этом режиме модель упорядочивает проверенные факты; для первого знакомства достаточно шаблона.

## 3. Выбрать решение и выполнить экспорт

Русские подписи в поле **«Решение»** обозначают следующие действия:

| Действие | Последствие |
|---|---|
| Одобрить учебный отчёт | После сохранения становится доступен локальный экспорт. |
| Отклонить отчёт | Сохраняется отклонение; экспорт недоступен. |
| Запросить изменения | Сохраняется запрос изменений; автоматическое исправление отчёта не запускается. |

Обоснуйте решение своими словами: что сверили и почему выбрали действие. Пустое обоснование сохранить нельзя. Несохранённый выбор и текст сохраняются при переходах между этапами в текущем сеансе браузера; после перезагрузки страницы, потери сеанса или перезапуска сервиса их сохранность не гарантируется. Для долговременного хранения нужно нажать **«Сохранить учебное решение»**.

Перед экспортом на этапе 5 прочитайте предупреждение и установите флажок **«Понимаю: после принятия экспорта решение по этой версии изменить нельзя»**. Нажмите **«Экспортировать в локальный симулятор»**. После подтверждения доставки нажмите **«Скачать сохранённый учебный отчёт»** — загрузится JSON-файл.

**Принятие экспорта блокирует изменение решения по этой версии отчёта.** Блокировка может уже действовать, даже если операция доставки ещё показана как ожидающая (`pending`): принятие и публикация результата выполняются отдельно. В этом случае повторите существующую операцию доставки, чтобы получить её результат; новое решение сохранить нельзя. При ошибке доставки используйте повтор существующей операции. Если экспорт не был принят, решение ещё можно изменить. После сохранения новой ревизии повтор старой доставки недоступен: для нового одобрения создайте новый экспорт с отдельным подтверждением.

Для регистрации случая на ручной разбор нажмите **«Зарегистрировать в локальной учебной очереди»**. Это запись в местном симуляторе: получатель не назначается, уведомление специалисту и отправка в банковскую систему не выполняются.

## 4. Вернуться к работе или остановить сервис

Сохранённые результаты доступны между запусками. В боковой панели выберите нужное задание по инциденту, дате и состоянию, затем откройте его. Для просмотра истории, отчётов и сохранённых решений подготовка поиска не нужна.

Если решение изменилось в другом сеансе, интерфейс сообщит о конфликте. Нажмите **«Перечитать сохранённое решение»**, сравните его со своим текстом и только затем повторите сохранение, если это всё ещё нужно. **«Обновить состояние»** обновляет состояние сервиса, но не подменяет версию решения, на основании которой вы начинали редактирование.

Если задание ещё выполняется, нажмите **«Отменить задание»** и обновите состояние. Для остановки автономного сервиса нажмите **Ctrl+C в терминале, где запущен Streamlit**, дождитесь возврата приглашения командной строки. Закрытие вкладки браузера сервер не останавливает. Сохранённые отчёты и решения останутся доступны после повторного запуска. В интегрированном режиме остановка UI оставляет API и его задания работать; порядок остановки всех компонентов приведён в [инструкции Kafka → AML](kafka-aml-quickstart.md).

## Если возникла проблема

| Что видно | Что сделать |
|---|---|
| «Создать задание» недоступна | Прочитать пояснение рядом с кнопкой: проверить идентификатор, подтвердить учебный режим, подготовить поиск или дождаться завершения текущего задания. |
| Поиск не готов (`not_ready`) после подготовки | Прочитать показанную причину и код ошибки. После исправления причины повторить подготовку; бесконечно ждать не нужно. При необходимости проверить терминал сервиса. |
| Отчёт не сформирован (`refused`) | Прочитать причину отказа. Отказ не является готовым отчётом; доступна локальная учебная очередь. |
| Истекло время / задание отменено (`timed_out` / `cancelled`) | Проверить готовность поиска; при необходимости подготовить его и создать новое задание. |
| Изменилась сохранённая версия (`VERSION_CONFLICT`) | Нажать «Перечитать сохранённое решение», сверить актуальное решение и только затем повторить сохранение. |
| Решение заблокировано после экспорта | Использовать просмотр решения и скачивание. Если доставка ещё не подтверждена, повторить существующую операцию. |
| `NOT_READY` при открытии или занят порт 8501 | Проверить, не работает ли уже этот сервис в другом терминале. Не запускать второй экземпляр или CLI-анализ одновременно с этим UI. |
| Не подтверждены источники | Решение и экспорт заблокированы. Сохранить идентификатор задания для разбора; доступна учебная ручная очередь. |
| Событие Kafka не видно в интерфейсе | Проверить надпись «Интегрированный режим», обновить состояние и раскрыть «Запросы AML из Kafka». Если запрос ещё `queued`, проверить готовность поиска и терминал `Run-AmlWorker.ps1`. История автономного UI отдельная. |
| В интегрированном режиме API недоступен | Запустить `Start-Lab.ps1` и обновить состояние. Сохранённую историю можно открыть без API; подготовка, создание и отмена заданий требуют его доступности. |

Для разбора ошибки сохраните идентификатор задания и код ошибки; технические сведения и сохранённые события обработки доступны в раскрываемых блоках.

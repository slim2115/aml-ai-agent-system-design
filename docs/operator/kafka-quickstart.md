## 1. Один раз подготовить Windows

Откройте отдельный PowerShell **от имени администратора** и установите WSL без дополнительного дистрибутива:

```powershell
wsl --install --no-distribution
```

Если Windows запросит перезагрузку, сохраните работу и перезагрузите компьютер самостоятельно. Затем выполните:

```powershell
wsl --update
wsl --version
```

Команда и её параметры описаны в [документации Microsoft](https://learn.microsoft.com/en-us/windows/wsl/basic-commands). Установите [Docker Desktop для Windows, x86_64](https://docs.docker.com/desktop/setup/install/windows-install/), выберите WSL 2 и самостоятельно ознакомьтесь с условиями при первом запуске. Дождитесь готовности Linux engine. Docker требует WSL версии не ниже 2.1.5.

Полностью закройте и заново запустите VS Code после установки, чтобы он получил обновлённый `PATH`; затем откройте новый терминал. Проверка:

```powershell
docker version
docker compose version
docker info --format '{{.OSType}}'
```

Последняя команда должна вывести `linux`. Если отображается ошибка подключения, сначала запустите Docker Desktop. Дальнейшие команды выполняются в обычном терминале, без прав администратора.

## 4. Отправка из Swagger

Откройте [Swagger](http://127.0.0.1:8765/docs). В первом терминале скопируйте локальный ключ:

```powershell
$labAccess = Get-Content .\var\postgres\lab-connection.json -Raw | ConvertFrom-Json
$labAccess.api_token | Set-Clipboard
```

В Swagger нажмите **Authorize**, вставьте ключ без слова `Bearer`, нажмите **Authorize → Close**. Откройте группу Kafka и её **POST /lab/kafka/events → Try it out**.

Подготовьте новый идентификатор события и время; команда копирует готовое тело в буфер:

```powershell
$eventBody = [ordered]@{
    event_id = [guid]::NewGuid().ToString()
    occurred_at = [DateTime]::UtcNow.ToString('o')
    incident_id = 'INC-000123'
    schema_version = 1
    event_type = 'incident.review.requested.v1'
    synthetic = $true
} | ConvertTo-Json
$eventBody | Set-Clipboard
```

Вставьте JSON в поле запроса и нажмите **Execute**. Сохраните `event_id` и исходное тело: они пригодятся для чтения результата и повтора.

**202** означает, что Kafka подтвердил запись сообщения. Обработка и запись результата в PostgreSQL происходят следом. В терминале обработчика появится `processed`; повтор того же события может дать `duplicate`.

Через **GET /lab/kafka/results/{event_id}** можно прочитать результат прямо в Swagger. **200** подтверждает запись в БД; **404 / KAFKA_RESULT_NOT_FOUND** означает только отсутствие результата в данный момент. Проверьте обработчик, отставание группы и DLQ, прежде чем делать вывод о доставке. **GET /lab/kafka/results** показывает последние результаты, а **GET /lab/kafka/status** отдельно проверяет Kafka и БД; этот статус не проверяет работающий процесс обработчика.

**503** означает недоступность зависимости или неопределённый результат отправки. При потере подтверждения сообщение могло попасть в Kafka. После восстановления повторяйте **то же тело с тем же `event_id`**. Новый идентификатор означает новое событие.

## 5. Посмотреть результат SQL-запросом

В первом терминале откройте SQL:

```powershell
.\scripts\lab\Open-Sql.ps1
```

В приглашении `aml_lab=>` выполните:

```sql
SELECT event_id, incident_id, processed_at, topic, partition, offset_value, result_json
FROM kafka_lab.processed_events
ORDER BY processed_at DESC
LIMIT 10;

SELECT event_id, partition, offset_value, duplicate, recorded_at
FROM kafka_lab.deliveries
ORDER BY recorded_at DESC
LIMIT 10;
```

`processed_events` хранит один результат на идентификатор события. `deliveries` показывает обработанные позиции Kafka: новый повтор сообщения получает новую позицию и отметку `duplicate = true`. При повторной доставке той же позиции отдельная строка не добавляется. Обе таблицы доступны учебному SQL-пользователю для чтения.

Для выхода в PowerShell введите `\q`. Перейдите к [упражнениям](../../lab/kafka/exercises.md).

## 6. Остановка и диагностика

Сначала завершите обработчик через **Ctrl+C**. Если параллельно запущен AML-поток, дождитесь завершения или отмените его задания и остановите AML-обработчик; API и брокер общие. Затем в первом терминале:

```powershell
.\scripts\kafka\Broker.ps1 -Action Stop
.\scripts\lab\Stop-Lab.ps1
```

Данные Kafka сохраняются в Docker volume; PostgreSQL — в существующем каталоге проекта. Сообщения Kafka имеют ограниченный срок хранения: 7 дней или около 128 МиБ на раздел, с удалением целых сегментов. Это учебное хранение, а не резервная копия результатов.

Полезные команды после запуска:

```powershell
.\scripts\kafka\Broker.ps1 -Action Status
.\scripts\kafka\Broker.ps1 -Action Topics
.\scripts\kafka\Broker.ps1 -Action Lag
.\scripts\kafka\Broker.ps1 -Action ReadDlq
```

`Lag` показывает разницу между доступными сообщениями и зафиксированным прогрессом группы. До первого запуска обработчика группа может отсутствовать. `ReadDlq` читает до 20 сообщений из каждого раздела топика ошибок; пустой раздел заканчивается по короткому тайм-ауту.

Если обработчик вывел `failed` и завершился, восстановите зависимость и запустите `Run-Worker.ps1` снова. Неподтверждённая позиция будет прочитана повторно, пока сообщение хранится в Kafka. Сбой БД останавливает обработчик; неверное сообщение уходит в DLQ. Kafka и PostgreSQL фиксируют прогресс раздельно, поэтому доставка может повторяться; уникальность `event_id` защищает результат от дублирования.

При работающих API, PostgreSQL, брокере и обработчике во втором терминале выполните в первом:

```powershell
.\scripts\kafka\Test-KafkaLab.ps1
```

Проверка отправляет одно новое синтетическое событие дважды, ждёт записи в БД и проверяет отсутствие второго результата. Запись остаётся для просмотра SQL; идентификатор и отчёт сохраняются в `var/checks/kafka-cycle/`. Команда не запускает службы и не заменяет упражнения со сбоями. На этой машине проверка успешно выполнена 02.10.2026; начните собственную практику с отправки события через Swagger в разделе 4.

Стенд рассчитан на локальную практику: один брокер, одна копия сообщения, доступ только с этой машины. При потере контейнерного хранилища восстановление Kafka из PostgreSQL автоматически не выполняется.

# DBeaver: учебный SQL без терминала

Основная установка и полный рабочий цикл собраны в [единой инструкции](service-and-lab.md). Команды этого справочника выполняются из корня вашей копии. Упоминания сохранённых прогонов относятся к указанной дате; их локальные архивы не входят в обычный клон.

Актуально на 20.10.2026. DBeaver Community — графический клиент для уже существующей PostgreSQL. Он открывает ту же базу, с которой работает [Swagger](http://127.0.0.1:8765/docs): новый сервер и перенос данных не требуются. Подготовка клиента и запуск стенда выполняются средствами проекта.

## 1. Начать занятие

1. В Проводнике откройте `.\lab\desktop`.
2. Откройте **AML SQL API - Start.lnk**. Он проверяет готовность PostgreSQL и API, затем открывает DBeaver с отдельным рабочим пространством проекта. После перезагрузки Windows повторите этот шаг. Подождите запуска: подготовка серверов может занять около минуты. Если клиент уже запущен, ярлык не открывает второй экземпляр: вернитесь в его окно через **Alt+Tab**.
3. В DBeaver выберите подключение **AML — практика** для упражнений или **AML — просмотр** для проверки результатов API/Kafka.
4. Для HTTP-запросов откройте [Swagger](http://127.0.0.1:8765/docs) в браузере. SQL работает в DBeaver, API — в Swagger.

При самом первом запуске может появиться мастер первоначальной настройки. Завершите его кнопкой **Finish / Готово**; если главное окно ещё не видно, проверьте **Alt+Tab**. Затем в дереве появятся оба подключения AML. На новой машине мастер нужно пройти самостоятельно.

Повторный запуск сохраняет данные. Клиент и стенд не готовят модели и не запускают Kafka или её обработчики. Для интеграционных занятий продолжайте по [маршруту SQL → API → Kafka](integration-practice.md) либо [Kafka → AML](kafka-aml-quickstart.md).

## 2. Подключения и первый вход

| Параметр | AML — практика | AML — просмотр |
|---|---|---|
| Драйвер | PostgreSQL | PostgreSQL |
| Сервер / порт | `127.0.0.1` / `55432` | `127.0.0.1` / `55432` |
| База | `aml_lab` | `aml_lab` |
| Пользователь | `aml_student` | `aml_reader` |
| Запись | В схеме `practice` | Запрещена правами БД |
| Фиксация изменений | Manual commit | Auto-commit |
| Часовой пояс | UTC | UTC |
| Порядок схем | `practice,reference,pg_catalog` | `practice,reference,pg_catalog` |

Пароль загружается автоматически из локальной конфигурации стенда через `scripts/lab/Get-DBeaverPassword.ps1`. В настройках подключения используется **Password from shell command**. При первом подключении DBeaver может запросить разрешение выполнить команду: проверьте, что она указывает на этот файл внутри `.` и роль `student` либо `reader`, затем разрешите её выполнение. Защитное подтверждение выполняете вы в окне клиента. Самостоятельно запускать помощник в терминале не нужно: его вывод содержит пароль.

Драйвер **AML PostgreSQL (local)** уже подготовлен локально. Первоначальную загрузку JDBC-драйвера повторять не требуется. Если появился мастер создания нового подключения, закройте его: используйте два подготовленных подключения. Пароль и ключ API не записываются в ярлыки или инструкции.

Настройки соединения можно проверить через **Edit Connection / Изменить соединение**. Для этого локального подключения SSH-туннель и SSL не требуются. В **Initialization / Инициализация** для «Практики» отключён Auto-commit. `search_path` задан свойством драйвера `options`; UTC и путь локального драйвера сохранены в `dbeaver.ini`. Открывайте клиент через подготовленный ярлык: он также выбирает рабочее пространство проекта и запускает PostgreSQL/API. После изменения настроек переподключитесь.

Порт `55432` относится к обычному учебному стенду. Порт `56432` и временные QA-базы из инструкций тестирования здесь не используются.

## 3. Первый запрос и таблицы

Выберите подключение → **SQL Editor → New SQL Script** либо откройте [dbeaver-start.sql](../../lab/sql/dbeaver-start.sql). Если вкладка файла показывает **`<none>`**, выберите **AML — просмотр** или **AML — практика** в списке подключения на панели SQL-редактора. Проверьте имя подключения в верхней части редактора и выполните запрос через **Ctrl+Enter**:

```sql
SELECT current_database() AS database_name,
       current_user AS role_name,
       current_setting('TimeZone') AS timezone,
       current_setting('search_path') AS search_path;
```

Ожидаются `aml_lab`, выбранная роль, `UTC` и `practice,reference,pg_catalog` (пробелы в выводе допустимы). Затем:

```sql
SELECT * FROM practice.clients ORDER BY client_id;
SELECT id, incident_id, body, revision FROM practice.case_notes;
```

Результат появится таблицей под редактором. В дереве **Database Navigator** раскройте `aml_lab → Schemas → practice → Tables`; открытие таблицы показывает её структуру и данные. Для чтения новых результатов повторите SELECT или обновите вкладку данных. Уже открытая таблица сама по себе не подтверждает актуальность результата.

Сохраняйте собственные SQL-файлы, например в `var/practice-sessions`. Для упражнений откройте [exercises.sql](../../lab/sql/exercises.sql); сверяйтесь с [solutions.sql](../../lab/sql/solutions.sql). Оба файла содержат стандартный PostgreSQL SQL. Шаблон `schema.sql` вручную не запускайте: его использует настройка стенда.

## 4. Commit, Rollback и API

В подключении **AML — практика** изменения выполняются внутри транзакции:

- **Commit** сохраняет все ещё не подтверждённые изменения этого соединения. После этого их увидит API и другое подключение DBeaver.
- **Rollback** отменяет все ещё не подтверждённые изменения этого соединения.
- Если редактировали ячейку в таблице, сначала примените изменение кнопкой **Save / Сохранить** редактора данных; затем подтвердите транзакцию через **Commit**. До применения ячейки SQL может ещё не быть отправлен серверу.

Не оставляйте транзакцию открытой между занятиями: она может удерживать блокировки. После ошибки SQL сделайте Rollback, прежде чем продолжать. Перед сменой режима фиксации сначала явно завершите текущую транзакцию.

Для тренировки отката создайте заметку через Swagger `POST /lab/notes` и сохраните её `id`. Подключитесь как «Практика», замените UUID ниже на полученный и выполните:

```sql
UPDATE practice.case_notes
SET body = 'Проверяю откат в DBeaver',
    revision = revision + 1,
    updated_at = clock_timestamp()
WHERE id = '00000000-0000-4000-8000-000000000001'::uuid
RETURNING id, body, revision;
```

Ожидается одна строка. В этом соединении виден новый текст; `GET /lab/notes/{note_id}` пока показывает сохранённый прежний текст. Нажмите **Rollback** и повторите SELECT: прежние текст и ревизия сохранятся. Если UPDATE вернул 0 строк, проверьте UUID — фиксация не создаст отсутствующую заметку.

Задания **11–12** и полный файл решений содержат собственные `BEGIN`/`ROLLBACK`. Для них сначала завершите текущую транзакцию, временно включите **Auto-commit**, затем выполните полный блок упражнения от `BEGIN` до завершающего `ROLLBACK` в отдельном редакторе. Не запускайте только середину блока. Если выполнение остановилось на ошибке, выполните `ROLLBACK;`. После занятия верните «Практике» **Manual commit**. Так собственный откат упражнения не отменит ранее оставленные изменения.

## 5. Проверить API и Kafka через SQL

Для наблюдения удобно подключение **AML — просмотр**: оно читает подтверждённые данные, не оставляя ручную транзакцию между проверками.

| Область | Что проверять |
|---|---|
| `practice` | Изменяемые таблицы и заметки Swagger `/lab` |
| `reference` | Исходный синтетический набор для сравнения и обработки сводки |
| `kafka_lab.processed_events`, `deliveries` | Результаты сводки и повторные доставки Kafka |
| `kafka_lab.analysis_requests`, `analysis_deliveries` | Связь события Kafka с AML-заданием и его проекцией |

Схема `kafka_lab` появляется после подготовки Kafka-практикума. Отсутствие этой схемы не мешает обычным SQL/API-упражнениям. Для примеров с UUID подставляйте идентификатор именно своего события в каждый SQL-фильтр.

SQL-изменения сами по себе не отправляют сообщения Kafka. Данные `practice` не являются источниками полного AML-анализа: он использует зафиксированные файловые источники. Решения оператора и экспорт хранятся в SQLite; PostgreSQL показывает учебную проекцию задания.

## 6. Закончить занятие

1. В каждом изменявшем данные соединении явно выберите Commit или Rollback.
2. Отключите подключения DBeaver; сохраните SQL-файлы.
3. Если запускали Kafka/AML, сначала завершите задания и остановите соответствующие обработчики и брокер по их инструкциям.
4. Откройте **AML SQL API - Stop.lnk** из `lab\desktop` и подтвердите остановку в появившемся окне.

Закрытие DBeaver или Swagger не останавливает PostgreSQL и API. Остановка сервера прерывает оставшиеся соединения; незавершённые транзакции откатываются. Уже подтверждённые данные сохраняются. Ярлык остановки не останавливает общий Docker, Ollama или самостоятельные процессы Kafka.

## 7. Если что-то не работает

| Наблюдение | Что сделать |
|---|---|
| Connection refused / сервер недоступен | Повторить запуск учебного стенда; проверить адрес `127.0.0.1:55432` |
| `pg_hba.conf rejects connection ... user "safa0"` | В старом профиле был пропущен пользователь БД. Закрыть DBeaver и выполнить восстановление профилей ниже. Ожидаются `aml_reader` / `aml_student`; разрешать вход `safa0` в PostgreSQL не требуется |
| Запрос разрешения выполнить команду | Проверить путь к `Get-DBeaverPassword.ps1` и роль, разрешить в DBeaver; затем повторить соединение |
| Password authentication failed / помощник вернул ошибку | Проверить, что выбран Password from shell command и соответствующая роль; локальная конфигурация должна существовать. API-ключ сюда не подходит |
| Driver files missing / неизвестный драйвер / `empty sample URL template` | Закрыть DBeaver, выполнить `Setup-DBeaver.ps1` и открыть ярлык проекта. Это восстанавливает параметры локального драйвера в `dbeaver.ini`; если пакет или JAR удалён — использовать `-Download` |
| Permission denied при записи | Выбрать «AML — практика» и таблицу `practice`; запись в `reference` и `kafka_lab` запрещена |
| API показывает старые данные | Применить изменения таблицы, выполнить Commit, повторить API-запрос; проверить UUID и схему |
| Запрос ждёт, ошибка transaction aborted | Проверить другие открытые транзакции; после ошибки выполнить Rollback |
| Нет новой таблицы/схемы в дереве | Обновить Database Navigator; проверить, выполнена ли подготовка соответствующего практикума |

Ошибки PostgreSQL/API находятся в `var/logs/postgres-lab.log` и `var/logs/lab-api.err.log`. Терминальные команды остаются резервным способом: `scripts/lab/Start-Lab.ps1`, `Open-Sql.ps1` и `Stop-Lab.ps1`; полный разбор — в [инструкции SQL/API](sql-api-quickstart.md).

Официальные справки: [DBeaver Community](https://dbeaver.io/download/), [режимы транзакций](https://dbeaver.com/docs/dbeaver/Auto-and-Manual-Commit-Modes/).

Первоначальные 19 проверок JDBC/API подтвердили права и работу SQL/API, но не выявили ошибку имени пользователя в профилях DBeaver. После сообщения об ошибке от 20.10.2026 выполнена отдельная проверка реальных подключений клиента (локальный материал: `verification/dbeaver-user-fix-2026-10-20/summary.md`). Первое подключение «Практика» может отдельно запросить разрешение команды для роли `student`.

## Подготовка и резервный запуск из VS Code

На этой машине пакет находится в `var/tools/dbeaver-26.2.3/dbeaver`, настройки и SQL-файлы рабочего пространства — в `var/dbeaver/workspace`. Обычная повторная настройка сохраняет подключения и ваши SQL-файлы; параметры UTC и драйвера обновляются с резервной копией `dbeaver.ini`. Закройте DBeaver перед настройкой:

```powershell
# Терминал открыт в корне вашей копии проекта.
.\scripts\lab\Setup-DBeaver.ps1
.\scripts\lab\Start-SqlDesktop.ps1
```

Для восстановления старых профилей с ошибочным пользователем `safa0`, при закрытом DBeaver:

```powershell
# Терминал открыт в корне вашей копии проекта.
.\scripts\lab\Setup-DBeaver.ps1 -RepairUsers
.\scripts\lab\Start-SqlDesktop.ps1 -ConnectRole reader
```

Восстановление изменяет имена пользователей только двух проверенных AML-профилей, сохраняет прочие подключения и SQL-файлы, создаёт резервную копию в `var/dbeaver/backups`. Проверить активные подключения без вывода паролей можно командой `.\scripts\lab\Test-DBeaverSessions.ps1 -RequireBoth`: перед этим подключите обе роли в DBeaver. `PASS` означает, что PostgreSQL видит реальные сессии клиента под обеими учебными ролями.

Если проверенных файлов пакета или драйвера нет, настройка с `-Download` скачает закреплённые версии и проверит SHA-256. Это требуется только для подготовки, не для каждого занятия. Остановка из VS Code: `.\scripts\lab\Stop-SqlDesktop.ps1`.

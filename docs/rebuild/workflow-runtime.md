# Сохраняемый учебный процесс — блок 5

Текущий пользовательский путь — `WorkflowService`, CLI `scripts/run_workflow.py`
и Streamlit `src/ui/app.py`. Они сохраняют задания, отчёты, решения и локальные
квитанции в SQLite внутри `var/workflow`. Исходный проект и аудит не изменяются.
В интегрированном режиме обработчиком владеет HTTP API на 8765, а UI обращается к нему. PostgreSQL содержит учебные таблицы и Kafka inbox; отчёты и решения остаются в SQLite. Автономная история — `var/workflow/workflow.sqlite3`, интегрированная — `var/workflow/api-workflow.sqlite3`. Полная установка и ежедневная работа описаны в [руководстве оператора](../operator/service-and-lab.md).

## Подготовка и предел времени

Контроллер получает эксклюзивную файловую блокировку базы. Второй контроллер
той же базы отклоняется; чтение, решения, отмена и доставка через отдельный CLI
доступны. Только владелец блокировки восстанавливает прерванные задания.
Автоматического повторного вызова модели после перезапуска нет.

Кнопка «Подготовить поиск» запускает отдельный процесс Windows spawn.
Он проверяет локальные артефакты embedding, загружает индекс и публикует готовность.
На подготовку отведено до 180 секунд; до её окончания задания не принимаются.
Это готовность embedding/индекса, а не проверка доступности или прогрев Ollama.
В режиме `local-model` недоступность Ollama возвращается безопасной ошибкой задания.
Автоматического скачивания моделей или запуска Ollama нет.

После приёма задания его сохранённый дедлайн включает запуск обработки, IPC,
контекст, генерацию и проверку. Процесс обслуживает одно задание; повтор с прежним
ключом возвращает исходный ответ приёма, новый запрос при занятости — `NOT_READY`.
Индекс используется повторно, но хеши артефактов проверяются до и после работы.

Родитель следит за monotonic-дедлайном независимо от вычислений дочернего процесса.
По истечении срока публикуется `timed_out`; поздний отчёт отвергается. При отмене
сначала сохраняется `cancelled`, затем останавливается обработчик. Отмену из другого
CLI контроллер замечает через сохранённое состояние. После таймаута или отмены
нужна повторная подготовка. Явное закрытие владельца окончательно: отложенный запуск
не может создать новый процесс после `close()`.

Остановка использует terminate/kill и ограниченные ожидания завершения. Это не
гарантия реального времени ОС: планировщик, файловая блокировка SQLite и завершение
процесса добавляют задержку. Ошибка сохранения удерживает приём закрытым до
подтверждения терминального состояния; при перезапуске применяется восстановление.
Остановка Python-клиента также не доказывает прекращение вычисления в отдельном
сервере Ollama. Холодный сбой 280,828 с из блока 4 остаётся в истории; новый механизм
не превращает единичные проверки в подтверждённые p95 или SLA.

`src.agent.AMLAgent` остаётся синхронным вычислительным ядром. Прямой вызов его
`run()` не предоставляет процессную отмену; пользовательские CLI/UI вызывают ядро
через управляемый процесс. `run_investigation.py --demo` — совместимый адаптер,
который теперь также сохраняет задание, но выводит прежний `InvestigationResult`.

## Работа в PowerShell

```powershell
& '.\scripts\rebuild\Enter-LocalEnvironment.ps1'
$amlPython = '.\.venv\Scripts\python.exe'
$amlWorkflow = '.\scripts\run_workflow.py'
& $amlPython -I -B $amlWorkflow run INC-000123 --demo --engine template
& $amlPython -I -B $amlWorkflow list
```

Для режима ограниченной локальной генерации замените `template` на `local-model`.
Без `--demo` возвращается `POLICY_NOT_APPROVED`. `run` выводит терминальный `Job`;
коды завершения: успех `0`, отказ `2`, ошибка/таймаут/отмена `3`.
`--database` задаётся перед подкомандой и принимает только путь внутри `var/workflow`.
UI и CLI `run` не могут одновременно владеть одной базой.

```powershell
& $amlPython -m streamlit run '.\src\ui\app.py' --server.address 127.0.0.1
```

В UI включите синтетический режим, подготовьте обработчик, обновите состояние
и создайте задание. Результат и историю можно читать после повторного открытия.
В раскрывающихся основаниях факта видны проверенные исходные ячейки: файл,
JSON Pointer, идентификатор строки, значение и SHA-256. Для агрегата показаны все
участники. Раздел нормы раскрывает точную редакцию и диапазон символов фрагмента.
Просмотр повторно проверяет текущий снимок и сохранённый отчёт, без загрузки
модели. При недоступном/изменённом источнике новое решение и экспорт блокируются;
сохранённый отчёт и учебная ручная очередь остаются доступны.
В интерфейсе это ограничение распространяется и на повтор ожидающего/неуспешного
экспорта. Для продолжения через UI нужно восстановить доступность источников.
Уже сохранённая квитанция при этом не отменяется: CLI `dispatch` может опубликовать
её без повторного принятия. Сервис доставки связывает принятие с сохранённым
одобрением и точными байтами отчёта, а UI дополнительно требует доступности оснований.
Изменение инцидента, режима или согласия скрывает прежние действия. Решение
привязано к показанным report/version/hash и ревизии; конфликт требует обновления.
Одобрение открывает учебный экспорт с сохранением квитанции и скачиванием точных
байтов отчёта. Ручная очередь доступна и для отказа, ошибки, таймаута или отмены.
Кнопка повтора возобновляет существующую доставку; новое создание с новым ключом
означает отдельную доставку.

CLI поддерживает `get JOB_ID`, `cancel JOB_ID --key KEY`,
`events JOB_ID` для чтения сохранённых этапов/попыток,
`decide --request decision.json --key KEY`, `deliver --request delivery.json --key KEY`
и `dispatch DELIVERY_ID --revision N`. JSON-тела используют v1 `DecisionRequest`
и `DeliveryRequest`; actor, время и квитанцию формирует приложение. Создание
`deliver` сохраняет pending, а `dispatch` отдельно выполняет локальное принятие.
Повтор запроса с тем же ключом и изменённым телом отвергается.

## Границы результата

SQLite хранит служебное состояние workflow; учебный SQL-стенд использует отдельный PostgreSQL.
Идентичность — псевдоним локальной учётной записи ОС, не банковский IAM. Все
квитанции явно имеют `mode=local_simulator`. SHA-256 не является подписью;
одобрение и экспорт не закрывают банковский кейс. Внешние получатели отклоняются.
Отчёт остаётся ограниченным набором проверяемых фактов на синтетических данных;
предметная политика, независимая SME-проверка и бизнес-эффект не подтверждены.

Подробности: [хранилище](workflow-storage.md), [доставка](delivery-simulator.md),
[контракты](contracts-v1.md), [вычислительное ядро](runtime-v1.md).

## Повтор проверок

После установки `.venv-ci` выполните `.\.venv-ci\Scripts\python.exe -I -B scripts/rebuild/run_checks.py --output-dir var/checks/workflow-manual`. Для проверки AppTest/CLI выполните `.\.venv-ci\Scripts\python.exe -I -B scripts/diagnostics/qualify_ci_ui.py --output-dir var/checks/workflow-manual/ui`. Используйте новый каталог при следующем прогоне. Отдельный Playwright smoke и живые модельные эксперименты приведены в полной инструкции. Исторические архивы блока 5 остаются локально; они не нужны для запуска опубликованного проекта.

# Runtime v1: границы блока 4

Актуализировано 6 ноября 2026 года. Документ описывает синхронное ядро. Текущие CLI/UI и API вызывают его через управляемый процесс, сохраняют задания, решения и локальную доставку. Жизненный цикл описан в [workflow-runtime](workflow-runtime.md). Исторические измерения блока 4 ниже сохранены с указанием их границ.

Публичный `src.agent.AMLAgent` использует новые модули `src/runtime/`.
Конструктор не обращается к источникам, модели или индексу. `run()` возвращает
строгий контракт `draft`, `refusal` или `error`; внутренние ошибки и события
не смешиваются с содержимым отчёта. Старый граф со свободной генерацией заменён.
Остальные исходные модули и исторические тесты остаются материалом сравнения;
их прямой вызов не является исправленным runtime и не входит в приёмку.

Два явных ограничения нужны для честной работы с неподтверждённой предметной политикой:

- Обычный режим возвращает `POLICY_NOT_APPROVED`. Режим `demo` работает только с
  отдельным синтетическим снимком и явно обозначенной учебной политикой.
- Черновик состоит из проверяемых фактов. Модель упорядочивает полный каталог
  идентификаторов; текст фактов, суммы, доказательства и цитаты строит код.
  Пропуски, дополнения и свободные выводы отклоняются. Это ограничение функции,
  а не доказательство качества произвольного текста LLM. Выявление намерения,
  порогов, высокорисковых стран и юридической применимости не реализовано
  через догадки. `suspicious_patterns=[]`, `confidence=null`.

Синтетическая таблица `applicability` выбирает учебные фрагменты по типу сигнала.
Ранжирование проверяет только порядок кандидатов; все активные фрагменты выбранных
правил должны присутствовать. Для `velocity` в исходном корпусе нет основания:
результат `NO_APPLICABLE_RULE`, а не придуманное правило. Название поля контракта
`applicable_rules` не превращает учебные тексты в утверждённые нормативные решения.

Подробности: [контекст](context-v1.md), [поиск](retrieval-v1.md),
[генерация](generation-v1.md), [контракт и nullable confidence](contracts-v1.md).

## Запуск

```powershell
& '.\scripts\rebuild\Enter-LocalEnvironment.ps1'
& '.\.venv\Scripts\python.exe' -I -B '.\scripts\run_investigation.py' INC-000123 --demo --engine template
```

`template` не вызывает LLM, но использует настоящую локальную embedding-модель
для поиска. `local-model` включает ограниченную генерацию через уже работающий
Ollama `qwen2.5:14b`. Автозагрузка моделей и запуск Ollama не выполняются.
Без `--demo` получится отказ. CLI-коды: draft `0`, refusal `2`, error `3`.

```powershell
& '.\.venv\Scripts\python.exe' -I -B '.\scripts\run_investigation.py' INC-000123 --demo --engine local-model
& '.\.venv\Scripts\python.exe' -m streamlit run '.\src\ui\app.py' --server.address 127.0.0.1
```

UI выводит динамические значения через plain-text/JSON-компоненты. Изменение
инцидента или режима сбрасывает прошлый результат. Решение, ручная очередь и локальный экспорт выполняются слоем workflow. Электронной подписи и банковской доставки нет.

## Защитные границы

Транспорт допускает только literal loopback (localhost переводится в 127.0.0.1)
и разрешённую модель. HTTP-прокси, перенаправления, tool calls и удалённые fallback
не используются. Ограничены размер ответа и время ожидания. Повтор допускается
только для невалидного выбора каталога, не более двух попыток с общим сроком;
обратная связь содержит фиксированный код, без предыдущего ответа модели.

В модель не передаются свободные текстовые поля источников, контрагенты,
назначения платежей, ФИО, ИНН, PAN и реальные идентификаторы записей. События
содержат только сгенерированный correlation_id, этап, фиксированный код и номер
попытки. Нет raw response, reasoning trace или строк исключений. Текст правил
выводится как цитируемые данные и не включается в инструкции модели.

Общий monotonic-бюджет включает сборку контекста, модель и проверки. Просроченный
исход заменяется `DEADLINE_EXCEEDED`, включая ошибки и отказы. Это пока проверка
срока на границах синхронных операций: она не гарантирует прерывание зависшей
библиотеки/ОС ровно в срок. Изоляцию worker, отмену и долговечное состояние job обеспечивает текущий слой workflow. Один быстрый прогон не доказывает SLA или p95. В блоке 4 зафиксирован
неуспешный холодный запуск: `DEADLINE_EXCEEDED` вернулся после 280,828 с.
Последующие функциональные проверки проходят после явного прогрева; холодный
результат сохранён отдельно и не считается принятым.

Локальные SHA-256 подтверждают согласованность пакета, но не подпись, правовой
статус или полномочия человека. Python socket-перехватчики в тестах не заменяют
OS firewall/IAM. Реальное принятие оператором, независимый набор и бизнес-эффект
по-прежнему требуют внешних данных и экспертной оценки.

## Проверка

```powershell
.\.venv-ci\Scripts\python.exe -I -B scripts/rebuild/run_checks.py --output-dir var/checks/runtime-manual
.\.venv\Scripts\python.exe -I -B scripts/run_investigation.py INC-000123 --demo --engine template
```

Окружения и модель должны быть подготовлены. Для следующего прогона задайте новый каталог результатов. Первая команда проверяет код с контролируемыми зависимостями. Вторая использует настоящую MiniLM и сохраняет задание; выполняйте её при остановленном автономном UI, чтобы избежать двух владельцев одной workflow-базы. Для живого исследования LLM используйте `qa/tools/run_llm.py --output-dir var/qa/llm/runtime-manual --repeats 3` через основное окружение Python. SQL/API/Swagger уже реализованы отдельным слоем `src/lab`.

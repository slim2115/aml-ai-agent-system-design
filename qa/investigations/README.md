# Учебные расследования качества Dark Factory

Практикум этапа 9 учит связывать заключение о качестве с наблюдением, версией и границами проверки. Он использует функции предыдущих этапов: оценку кандидата и бюджет, статистику повторов, проверку файлов, обработчик и SQLite. Вызовов настоящей LLM, Kafka или PostgreSQL при подготовке пакета нет.

## Запуск

Из корня проекта в PowerShell 7, с установленным `.venv-ci`:

```powershell
$learningRun = 'learning-' + (Get-Date -Format yyyyMMdd-HHmmssfff)
.\.venv-ci\Scripts\python.exe -I -B qa/tools/build_investigations.py --run-id $learningRun
if ($LASTEXITCODE -ne 0) { throw 'Пакет не подготовлен; используйте новый run-id после диагностики' }
.\.venv-ci\Scripts\python.exe -I -B -m streamlit run qa/analyst/app.py --server.address 127.0.0.1 --server.port 8502 --server.headless true --browser.gatherUsageStats false
```

Откройте [локальный UI](http://127.0.0.1:8502), раздел «Учебные расследования», выберите пакет и случай. Если UI уже запущен, второй процесс не нужен. Создайте пакет в другом терминале и обновите страницу. Завершение UI — Ctrl+C. Установка окружения, упражнения и диагностика приведены полностью в [разделе 10.14 руководства](../../docs/operator/service-and-lab.md#quality-investigations).

## Шесть случаев

| Случай | Что нужно установить |
| --- | --- |
| L01 — исправление ответа | Первый FAIL сохраняется, даже если итоговый кандидат получил PASS; квалификация ожидаемого поведения имеет отдельный статус |
| L02 — расход токенов | Неизвестный расход не равен нулю; резерв и известная сумма не подтверждают полный итог |
| L03 — пропущенный повтор | Знаменатель задаёт план; отсутствие одного наблюдения сохраняет INCOMPLETE |
| L04 — зависимые наблюдения | Повторы и перестановки не создают новые независимые случаи; перенос на популяцию не установлен |
| L05 — изменение свидетельства | Несовпадение байтов обнаруживается по исходному хэшу; намеренно меняется только новый учебный файл |
| L06 — потеря HTTP-подтверждения | Повтор submit с тем же ключом создаёт один job; число вызовов и число эффектов различаются |

В каждом случае четыре факта `F01`–`F04`. Ответ включает вывод, причину, следующее действие, набор подтверждающих фактов и обоснование до 2000 символов. Варианты и ожидания заданы в `catalog-v1.json`. Кнопка «Проверить разбор» возвращает `PASS`, `FAIL` или `INCOMPLETE` по открытой рубрике. Пустые обязательные ответы не считаются успешным разбором; неизвестные идентификаторы и неверная структура отклоняются. Свободное обоснование сохраняется как `NOT_SCORED`.

## Артефакты и доверие

Генератор принимает новое имя из латинских букв, цифр, `_` и `-`, длиной до 64 символов; первый символ — буква или цифра. Повторное использование существующего каталога запрещено. Пакет хранится в `var/qa/investigations/<run-id>`, принадлежащая ему SQLite — в `var/workflow/investigations/<run-id>/http-ack-replay`. Оба каталога остаются локальными.

Пакет содержит копию рубрики, наблюдения, выбранные факты, квалификацию контролей, снимки исходников и окружения, итог и перечень хэшей. При незавершённой подготовке старый каталог сохраняется для диагностики; новый запуск получает другое имя. В L05 исходный хэш намеренно перестаёт соответствовать только созданному учебному файлу. Общий манифест пакета закрепляет его окончательное состояние; исторические результаты не редактируются.

Чтение ограничено фиксированными файлами пакета и его SQLite. Проверяются размеры, пути, структура JSON, хэши, пересчёт выбранных фактов и соответствие рубрики текущему каталогу. После изменения исходников пакет доступен для просмотра, но оценка ответа блокируется. Перед отправкой формы целостность проверяется повторно. Хэши не являются независимой подписью и не исключают согласованную подмену локальных файлов владельцем.

Ответ существует в браузерной сессии; кнопка «Скачать учебный разбор JSON» позволяет сохранить его локально. Исходный пакет сервер не изменяет. Файл содержит привязку к пакету, ответ и оценку по рубрике. Переключение случая не переносит заключение предыдущего разбора в новый.

## Браузерная проверка формы

При работающем UI и уже установленных фиксированных browser tools (команда `scripts/qa/Install-BrowserTools.ps1`, раздел 10.2 инструкции) выполните в отдельном терминале. В `$learningRun` укажите имя подготовленного пакета текущей версии:

```powershell
$learningRun = 'learning-ВАШЕ-ИМЯ'
$browserRun = 'learning-ui-' + (Get-Date -Format yyyyMMdd-HHmmssfff)
.\.venv-ci\Scripts\python.exe -I -B qa/tools/check_investigations_browser.py --run-id $learningRun --output-dir "var/qa/investigation-browser/$browserRun"
if ($LASTEXITCODE -ne 0) { throw 'Браузерная проверка не пройдена; сохраните result.json' }
```

Проверяются пустой, правильный и ошибочный ответы, сохранённый JSON, смена случая и границы оценки. Результаты и скриншоты остаются локально. Это автоматическая проверка формы, а не выполненное человеком упражнение. Инструмент не запускает сервер.

## Область подтверждения

Программная квалификация проверяет ожидаемые сигналы на фиксированных синтетических контролях. Это не новый замер качества реальной модели, отказоустойчивости живой инфраструктуры, SLA или знаний оператора. Открытая рубрика предназначена для самостоятельной практики, а не для независимого экзамена. `operator_practice=NOT_MEASURED`, `product_acceptance=INCOMPLETE`; исторический FAIL Judge и отложенная человеческая калибровка сохраняются.

Проверки каталога, оценивания, построения пакета, целостности и UI включаются в общую регрессию. Текущий итог этапа фиксируется отдельным прогоном; результаты предыдущей версии нельзя автоматически переносить на изменённые исходники.

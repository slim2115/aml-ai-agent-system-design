# Ограниченный автономный цикл ответа

Этап 7 проверяет цепочку «предложить порядок фактов → проверить кандидата → вернуть допустимый код ошибки → исправить или остановиться». Кандидат — JSON с перестановкой разрешённых идентификаторов. Его обрабатывают настоящий renderer сервиса и отдельная программная проверка по замороженным синтетическим данным.

Исходники, SQL, политика и эталоны не изменяются. Кандидат не исполняется как код. Этот цикл не является самостоятельной фабрикой разработки, автоматическим AML-решением или разрешением релиза. Полная установка окружения и учебный разбор находятся в [инструкции оператора](../../docs/operator/service-and-lab.md#bounded-response-cycle).

## Учебный запуск

Из корня проекта после подготовки `.venv-ci`:

```powershell
$autonomyRun = 'var/qa/autonomy/demo-' + (Get-Date -Format yyyyMMdd-HHmmssfff)
.\.venv-ci\Scripts\python.exe -I -B qa/tools/run_autonomy.py --output-dir $autonomyRun --mode demo
Get-Content "$autonomyRun/report.md" -Encoding UTF8
Get-Content "$autonomyRun/demo.json" -Raw -Encoding UTF8
```

Модель, PostgreSQL и Kafka для этого режима не нужны. Одиннадцать заранее объявленных контролей проверяют правильный первый ответ, исправление, отсутствие прогресса, предел попыток, лимиты вызовов/токенов/времени, тайм-аут, неизвестный расход, превышение резерва и ошибку оценщика. Генератор ответов и время синтетические; renderer, oracle, контроллер и управление дочерним процессом настоящие.

`demo` использует фиксированный набор: пользовательский `--case-id` и изменённые `--max-attempts`/`--max-tokens` предназначены для режима `ollama`. В `demo` принимаются стандартные значения 6/98304 без пользовательского выбора случаев; они не означают общий лимит шести попыток на все контроли. Отдельные контрольные бюджеты находятся в `demo.json`. `--wall-seconds` ограничивает реальное время внешнего процесса, а время внутри контролей остаётся виртуальным.

`qualification_status=PASS` означает совпадение наблюдений с ожиданиями контролей. Внутри отрицательного контроля может быть `FAIL`, `ERROR` или `INCOMPLETE`: именно такой исход должен обнаружить проверяющий инструмент.

## Ограниченный запуск локальной Ollama

Подготовьте Ollama и существующую модель `qwen2.5:14b` по основной инструкции. Используются только `127.0.0.1:11434` и закреплённый digest модели из действующего измерителя LLM; автоматического скачивания или смены модели нет. В этом эксперименте контекст и применимые правила берутся из проверенного замороженного каталога, поэтому MiniLM и живой поиск не измеряются.

```powershell
$autonomyRun = 'var/qa/autonomy/ollama-' + (Get-Date -Format yyyyMMdd-HHmmssfff)
.\.venv-ci\Scripts\python.exe -I -B qa/tools/run_autonomy.py --output-dir $autonomyRun --mode ollama --case-id QA-S01 --max-attempts 2 --max-tokens 32768 --wall-seconds 180
Get-Content "$autonomyRun/report.md" -Encoding UTF8
Get-Content "$autonomyRun/cycle.json" -Raw -Encoding UTF8
```

Для нескольких случаев повторите `--case-id`; разрешены `QA-S01`, `QA-S02`, `QA-S03`, `QA-S04`, `QA-S14`. В отдельном случае есть максимум две условные попытки. Общий `--max-attempts` ограничивает весь запуск; это предел вызовов, а не требование выполнить их все. Успех первого кандидата оставляет второй слот `NOT_NEEDED`. Не начатые из-за остановки случаи остаются `NOT_RUN`.

До каждого вызова резервируются **16 384 токена** из общего бюджета. Известный расход уточняется по ответу сервера; неизвестный сохраняет резерв и останавливает следующие вызовы. Это консервативный резерв, а не точный tokenizer или доказанная верхняя граница расхода провайдера. На запрос также установлен `num_predict=512`; сообщённое сервером превышение отклоняет кандидата. Назначение параметра описано в [документации Ollama](https://docs.ollama.com/modelfile#valid-parameters-and-values), поля фактического расхода `prompt_eval_count` и `eval_count` — в [контракте chat API](https://docs.ollama.com/api/chat).

Бюджет применяется перед каждым транспортным вызовом, без скрытого retry внутри адаптера. Старый `qa/tools/run_llm.py` остаётся самостоятельным измерителем; этот CLI не меняет бюджет уже сохранённых прогонов.

## Решение о продолжении

Базовый ответ строится и проверяется до выдачи данных генератору. Модель получает только фактический каталог, ключи правил и контракт ответа. При отказе допускаются три кода обратной связи: `INVALID_MODEL_JSON`, `INVALID_MODEL_RESPONSE`, `INCOMPLETE_OR_UNKNOWN_SELECTION`. Ответ оценщика, эталонный отчёт и произвольные инструкции обратной связи модели не передаются.

Первая неудачная попытка сохраняет `FAIL`, даже если следующий кандидат исправлен. Поэтому у исправленного случая `final_candidate_status` может быть `PASS`, а общий результат цикла — `FAIL`. Для оценки частоты ошибок читайте все попытки и `first_attempt_status`, а не только последний кандидат.

Повтор одинакового ошибочного текста завершает случай с `NO_PROGRESS`. Неисправимая ошибка oracle завершает случай; сбой оценщика, транспорта, часов или журнала, неизвестный расход и нарушение бюджета прекращают дальнейшие вызовы. Никакого «повторять до зелёного» нет. Эти условные repair-попытки не являются независимыми статистическими повторами этапа 6.

## Свидетельства и границы

| Артефакт | Что показывает |
| --- | --- |
| `result.json`, `report.md` | Итог контролируемого запуска, привязку к версии, состояние процесса и ограничения приёмки |
| `worker-config.json` | Объявленные режим, случаи, лимиты и версия исходников |
| `journal.jsonl` | Последовательность событий: резервирование до вызова, предложение, расход, оценка и остановка |
| `demo.json` | Ожидания и результаты 11 учебных контролей, все вложенные циклы |
| `baseline.json`, `cycle-plan.json` | Проверку базового ответа и фактический план живого цикла |
| `cycle.json` | Все попытки, первый и последний исходы, неиспользованные слоты, ledger и причины остановки |
| `candidates.json` | Последние успешно проверенные кандидаты, сохранённые как отдельные артефакты |
| `http-attempts.json` | Синтетические HTTP-запросы/ответы и телеметрию живого режима; файл остаётся локальным |
| `model-before.json`, `model-after.json` | Согласованность сохранённой идентичности локальной модели до/после |
| `source-*.json`, `environment-*.json`, `evidence.json` | Хэши версии, окружения и свидетельств |

Worker запускается фиксированной командой под существующим `run_owned`. Внешний тайм-аут и Windows Job ограничивают жизнь принадлежащего запуску клиентского процесса и его потомков. Это управление процессами, а не системная песочница. Ollama работает отдельным сервером: завершение клиента не доказывает прекращение серверного вычисления. Журнал сохраняется перед вызовом, поэтому при аварийной остановке видно незавершённое резервирование; оно не считается нулевым расходом или успешным результатом.

Изменение защищённых входов, несовпадение версии модели, нарушение целостности свидетельств или неподтверждённая очистка не позволяют признать запуск успешным. Локальные хэши не являются независимой подписью и не создают скрытый holdout. Семантическая полезность порядка, предметная AML-приёмка и калибровка Judge не измеряются: `candidate_admission=NOT_EVALUATED`, `product_acceptance=INCOMPLETE`.

Коды выхода: **0 PASS, 1 FAIL, 2 ERROR, 3 INCOMPLETE**. Каждый повтор требует нового имени каталога. `started.json` без `result.json` — незавершённый запуск; старые результаты не перезаписывайте. Commit, push и deployment этот инструмент не выполняет.

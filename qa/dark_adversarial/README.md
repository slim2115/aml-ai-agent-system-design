# Учебная проверка adversarial-входов

Сценарии из `probe.py` делают отдельные синтетические копии примера S14 и проверяют, попадает ли недоверенный текст в запрос модели или отчёт. Контекст и построение отчёта настоящие, embedding и transport — тестовые подмены. Вмешательство в вывод наблюдения дополнительно проверяет, обнаруживает ли оценщик подменённые факты и утечку маркера.

Это открытые вариации одного случая: они не доказывают устойчивость живой модели, не являются независимыми AML-кейсами или скрытым holdout. Проверки исходных файлов подтверждают их сохранность до/после измерения. Для результатов разрешён только новый каталог `var/qa/dark-adversarial/<имя>`.

Учебный прогон с сохранением синтетических входов и `result.json` (имя каталога должно быть новым):

```powershell
.\.venv\Scripts\python.exe -I -B qa/dark_adversarial/probe.py --output-dir var/qa/dark-adversarial/run-01
```

Проверка модуля:

```powershell
.\.venv\Scripts\python.exe -I -B -m pytest -c pyproject.toml tests/dark_adversarial -q -p no:cacheprovider
```

# Учебная проверка изоляции Docker

Этот эксперимент запускает **доверенный синтетический скрипт**, который удваивает число. Он не запускает AML-сервис и не проверяет Kafka. Образ `apache/kafka:4.3.1` используется только как уже доступная локальная среда с `/bin/sh`; образ выбирается по локальному ID и не скачивается. Его ID не является независимой подписью или аттестацией образа.

## Запуск

Откройте PowerShell в корне rebuild и подготовьте окружение:

```powershell
# Терминал открыт в корне вашей копии проекта.
& .\scripts\rebuild\Enter-LocalEnvironment.ps1
docker version
.\.venv\Scripts\python.exe -I -B qa/dark_isolation/probe.py --output-dir var/qa/dark-isolation/my-run-01
Get-Content var/qa/dark-isolation/my-run-01/result.json -Raw
```

Docker Desktop и локальный образ, указанный в измерителе, должны быть доступны. Выберите **новое** имя каталога для каждого запуска: существующие результаты не перезаписываются. Проверка использует `--pull=never` и не загружает образ. Если Docker или образ недоступен, статус будет `INCOMPLETE`. Код завершения `0` соответствует `PASS` только для конкретного эксперимента; `1` — `FAIL` или `INCOMPLETE`, а `2` — ошибка подготовки пути или записи результата.

Автоматические проверки самого измерителя с подменным Docker не требуют запуска Docker или LLM:

```powershell
.\.venv\Scripts\python.exe -I -B -m pytest -c pyproject.toml tests/dark_isolation -q -p no:cacheprovider
```

## Что проверяется

Измеритель создаёт собственный контейнер с уникальной меткой, затем проверяет его настройки через `docker inspect`: сеть `none`, корневую файловую систему только для чтения, непривилегированного пользователя, снятые capabilities, `no-new-privileges`, ограничения ресурсов и отсутствие подключённых каталогов хоста. Объявленные образом каталоги `VOLUME` перекрываются временными `tmpfs`; поэтому утверждение о режиме только для чтения относится к **корневой файловой системе**, а не ко всем путям контейнера.

В контейнер передаётся открытый синтетический ввод через stdin; сравнение с учебным ожидаемым ответом происходит на хосте. Скрипт также проверяет конкретный путь `/qa-private/answer`, путь сокета Docker и попытку записи в корень. После запуска измеритель удаляет только созданный им контейнер, предварительно сверяя его ID, имя и уникальную метку. Если принадлежность или очистку подтвердить не удалось, итог остаётся `INCOMPLETE`. При прерывании создания ресурс с неподтверждённым ID автоматически не удаляется.

## Границы результата

- `container_configuration: PASS` означает, что наблюдённые через `inspect` настройки совпали с ожидаемыми. Фактический сетевой трафик отдельно не проверялся; `network: CONFIGURED_NONE` описывает конфигурацию.
- Проверка отсутствия одного указанного пути и сокета не доказывает невозможность всех способов доступа или обхода. Вывод stdout самого доверенного скрипта не является независимым свидетельством поведения произвольного недоверенного кода.
- Владелец хоста, Docker и оценщик сохраняют доступ к локальным данным и управлению экспериментом. Разделение контейнера не создаёт независимый закрытый набор: `hidden_holdout: NOT_ESTABLISHED` и `independent_attestation: NOT_ESTABLISHED`.
- Результат относится только к арифметическому примеру и локальному окружению. Качество AML, Kafka, LLM и экспертная приёмка здесь не измеряются.

Первый сохранённый запуск `var/qa/dark-isolation/live-20261030-01/result.json` остался `INCOMPLETE` из-за ошибки передачи ввода; после исправления новый запуск `live-20261030-02/result.json` завершился `PASS` в описанной узкой области. Старый результат не перезаписан.

## Уточнения после аудита 30 октября 2026 года

Измеритель теперь отклоняет дополнительные capabilities, подключение пространств имён хоста и неожиданные пути `tmpfs`. Некорректные структуры `Labels` и `Mounts` не приводят к успешной проверке или разрешению очистки ресурса без подтверждения его принадлежности.

В новых результатах `evidence_schema: docker-isolation-v2` сохранены имя, уникальная метка и полученный ID контейнера (`resource`), проверенные поля `inspect` (`configuration_evidence`), stdout и код завершения кандидата, а также SHA256 исходника до и после выполнения. Переменные окружения образа и посторонние метки в снимок не включаются. Это локальные свидетельства для повторной проверки, а не независимая аттестация.

Если `docker create` прерван и ID не получен, `cleanup` остаётся `INCOMPLETE`; имя и метка позволяют найти возможный остаточный ресурс. Автоматическое удаление по одному имени не выполняется: для него требуется подтверждённый ID и совпадение метки.

Область эксперимента и ограничения выше сохраняются. Подробности — в отчёте аудита (локальный материал: `verification/dark-factory-audit-2026-10-30/summary.md`).

# Dark factory: кандидатный синтетический набор v2

Это **открытый разработочный набор**, а не скрытый holdout, независимый benchmark или экспертно утверждённая AML-разметка. Сценарии записаны до прогона и привязаны к документированным контрактам; изменение ожиданий требует новой версии и отдельного анализа. Контрольный SHA256 в `catalog.py` защищает от случайного изменения `cases.json`, но не является цифровой подписью или защитой от одновременной подмены кода и данных.

Девять машинных проб проверяют формат идентификатора и включительную/исключительную границы окна через реальные `classify_incident_id` и `InvestigationContext`. Для окна используется копия контекста существующего синтетического QA-S01; существующие файлы не изменяются. Значения введены вручную; реальные embedding/LLM, API, Kafka и поведение всего `ContextBuilder` здесь не запускаются. Идентификаторы семей указывают на риск-срез, **не доказывают статистической независимости**: оценки `independent_case_count` нет.

Шесть `unexecuted_hypotheses` — планы будущих проверок: ни одна из них не считается реализованным тестом, а результат модели и экспертное подтверждение отсутствуют. Данный набор не создаёт искусственные критические пороги и не подтверждает AML-приёмку. Приёмка человека и продукта: `INCOMPLETE`.

Запуск из корня проекта после подготовки окружения:

```powershell
.\.venv\Scripts\python.exe -I -B qa/datasets/dark-factory-v2/catalog.py
```

Вывод — JSON в терминал; существующие свидетельства и наборы не меняются. Системный статус `PASS` относится только к выполненным девяти контрактным пробам. Непредвиденная ошибка или несоответствие делает этот статус `FAIL`, а не положительным результатом по всем гипотезам. Для сохранения отдельного свидетельства используйте новый файл вне исходных наборов без перезаписи старых результатов.

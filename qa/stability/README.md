# Статистическая устойчивость и бюджет

Этап 6 Dark Factory анализирует заранее объявленную панель случаев и повторов. Пропущенные, ошибочные и остановленные наблюдения сохраняются в знаменателе. Результаты помогают разбирать качество измерений и расход ресурсов; продуктовая приёмка и перенос на реальную популяцию остаются незавершёнными.

## Учебный запуск

После подготовки `.venv-ci` по [основной инструкции](../../docs/operator/service-and-lab.md#statistical-stability) из корня проекта:

```powershell
$stabilityRun = 'var/qa/stability/demo-' + (Get-Date -Format yyyyMMdd-HHmmssfff)
.\.venv-ci\Scripts\python.exe -I -B qa/tools/run_stability.py --output-dir $stabilityRun
Get-Content "$stabilityRun/report.md" -Encoding UTF8
```

Команда выполняет фиксированные синтетические контроли, без сети, модели и БД. Два варианта проверяются на одних случаях и повторах. Есть намеренная ошибка, потерянное наблюдение и панель, остановленная бюджетом. Успешная квалификация означает, что ожидаемые ошибки обнаружены; она не превращает отрицательный пример в качественный ответ.

В `demo.json` сохранены входы, ожидаемые и наблюдавшиеся статусы, ограничения и ledger каждого контроля. Время виртуальное. Число семейств в панели не возрастает при увеличении числа повторов.

## Пересчёт сохранённых результатов LLM

Сначала получите собственный результат существующей команды `qa/tools/run_llm.py` по разделу реальных моделей основной инструкции. Затем передайте его каталог:

```powershell
$llmSource = 'var/qa/llm/имя-вашего-прогона'
$stabilityRun = 'var/qa/stability/history-' + (Get-Date -Format yyyyMMdd-HHmmssfff)
.\.venv-ci\Scripts\python.exe -I -B qa/tools/run_stability.py --source-dir $llmSource --output-dir $stabilityRun
Get-Content "$stabilityRun/report.md" -Encoding UTF8
Get-Content "$stabilityRun/historical-metadata.json" -Raw -Encoding UTF8
```

Существующий каталог не редактируется, LLM заново не вызывается. План и исходные повторы читаются из сохранённых файлов; доступные результаты повторно проверяются программным оценщиком. Хэши всех прочитанных файлов фиксируют входы пересчёта. Это не доказательство подлинности старой машины и не измерение новой версии модели. Локальный исторический pilot-first не входит целиком в Git; его отсутствие в новом клоне штатно.

Общий лимит вызовов/токенов/времени старый collector заранее не задавал. Поэтому `budget_enforcement=NOT_EVALUATED`: известное потребление можно посчитать, прежнее соблюдение несуществующего лимита подтвердить нельзя. BudgetLedger используется в учебном исполнителе и [отдельном цикле исправления ответа этапа 7](../autonomy/README.md); текущий `run_llm.py` автоматически к нему не подключается.

## Как читать статистику

| Файл / показатель | Значение |
| --- | --- |
| `result.json` | Статусы анализа, квалификации, привязки к версии и неизменности свидетельств |
| `plan.json`, `observations.json` | Объявленные варианты, случаи, семейства, повторы и нормализованные наблюдения |
| `statistics.json` | Полный знаменатель; доли по вариантам; состояние каждого случая/семейства; парные различия |
| Вариативность | Число различных смысловых/упорядоченных отпечатков среди минимум двух проверенных черновиков; отсутствие черновиков не означает стабильности |
| Задержка | p50/p95 методом ближайшего ранга, минимум/максимум и число измеренных значений; ошибки учитываются при наличии времени |
| Расход | Все HTTP-попытки, включая repair/error/timeout; известные суммы токенов и количество неизвестных измерений |
| `evidence.json` | SHA256 источников и выходов; локальные хэши, не независимая подпись |

Парное сравнение использует одинаковые case/repeat слоты baseline и candidate. Неполные пары не исчезают из планового знаменателя. Разница описательная, не p-value и не доказательство превосходства.

Каждое семейство получает один бинарный исход «все запланированные проверки успешны». Условный 95% интервал Wilson рассчитывается только при определённых исходах всех семейств; при пропусках он недоступен. Это вычисление при предположении независимых репрезентативных семейств. У наших отобранных синтетических случаев эти предпосылки **не установлены**: `population_inference=NOT_ESTABLISHED`. Интервал не допускает релиз автоматически. Формула соответствует [NIST/SEMATECH](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm); новых библиотек не требуется.

## Правила бюджета

`BudgetLedger` получает неизменные max_attempts, max_tokens и wall_seconds. Перед действием резервируется один вызов и консервативный объём всех токенов запроса/ответа. Одна активная попытка; каждый retry требует нового резерва. После завершения известный расход освобождает неиспользованный резерв. Неизвестный расход сохраняет весь резерв и статус неполного учёта. Превышение резерва, времени или ошибка часов блокируют новые попытки; прошлый расход не обнуляется.

Ledger контролирует допуск и замечает превышение после возврата. Он не убивает зависший callback, не принуждает провайдера соблюдать токены и не заменяет deadline транспорта и изоляцию процесса. Токены не переводятся в денежную стоимость, энергию или SLA. PASS ledger относится к учёту, а не качеству ответа.

Коды CLI: **0 PASS, 1 FAIL, 2 ERROR, 3 INCOMPLETE**. `started.json` без итогового `result.json` означает незавершённый запуск. Не правьте свидетельства вручную; каждый повтор требует нового каталога. Нет автоматического «повторять до зелёного». Человеческая калибровка и качество настоящего Judge здесь не переоцениваются.

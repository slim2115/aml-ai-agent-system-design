# SQL-практика

Стенд использует отдельную базу `aml_lab` на `127.0.0.1:55432`. Данные взяты из проверенного синтетического снимка прототипа: 5 клиентов, 4 карты, 5 инцидентов, 15 транзакций и 5 учебных правил. Таблица `case_notes` изначально пустая; это заметки для упражнений, а не решения AML-оператора.

| Область | Назначение | Права |
|---|---|---|
| `reference` | Эталон исходного снимка | Все учебные роли только читают |
| `practice` | Копия для SQL и API | `aml_student` меняет данные и создаёт/меняет таблицы |
| `practice.case_notes` | Учебный CRUD через API | `aml_api` читает и меняет заметки; остальные таблицы только читает |

`aml_reader` читает обе схемы. `aml_lab_admin` применяется только для настройки и явного восстановления. Пароли генерируются локально и находятся в `var/postgres/lab-connection.json`; не добавляйте этот файл в Git и не подставляйте пароли в опубликованные команды. Для SQL-клиента подходят DBeaver, pgAdmin или поставляемый со стендом `psql`; укажите адрес, порт, базу и выбранную роль в форме подключения. SSH/SSL для этого локального учебного подключения не нужны.

Начните с `exercises.sql`; решения и ожидаемые результаты лежат отдельно в `solutions.sql`. Первые десять заданий читают данные. Задания 11–12 используют транзакции и откат, поэтому их полный запуск не оставляет изменений. Проверки ожидают исходный снимок: после ваших SQL-изменений результаты могут отличаться. Запускайте файл решений вне собственной незавершённой транзакции.

Из корня новой копии проекта:

```powershell
.\.venv\Scripts\python.exe -I -B scripts\lab\database.py status
.\.venv\Scripts\python.exe -I -B scripts\lab\database.py bootstrap
```

`bootstrap` проверяет SHA-256 манифеста и файлов до загрузки, создаёт только отсутствующие схемы и не обнуляет уже созданную `practice`. При чужой немаркированной базе/роли/схеме он останавливается. Повторный запуск сохраняет ваши изменения.

Повторная проверка исходного набора, SQL-решений, ограничений и прав доступа без сброса `practice`:

```powershell
.\.venv\Scripts\python.exe -I -B scripts\lab\qualify_database.py
```

Результат сохраняется в `var/checks/lab/sql-qualification.json`. Успех выполненных проверок даёт `PASS`; отдельный тест восстановления честно отмечен `NOT_RUN`. Проверки ожидают исходный набор и поэтому могут сообщить об отличиях после ваших упражнений. Их изменения откатываются; запускайте проверку без параллельных SQL/API-записей. Для первичной приёмки можно явно указать `--output-dir verification/block-06`; обычный запуск сохраняет исторический отчёт. Ключ `--verify-reset` предназначен только для согласованной приёмки свежего стенда и в повторную проверку не входит.

Для намеренного удаления учебных изменений и заметок предусмотрено отдельное восстановление:

```powershell
.\.venv\Scripts\python.exe -I -B scripts\lab\database.py reset-practice --confirm-practice-reset
```

Оно в одной транзакции пересоздаёт только маркированную схему `practice`; `reference` сохраняется. Не запускайте его во время работы с API или открытой SQL-транзакцией. API и обычный запуск сервера не выполняют восстановление автоматически. Пользовательские таблицы и представления внутри `practice` также удаляются при восстановлении.

Денежные суммы хранятся в `numeric(38,2)`, Python читает их как `Decimal`. Суммируйте разные валюты отдельно. PostgreSQL округляет значение с дополнительными десятичными знаками при записи в `numeric(38,2)`; через API в этом блоке изменяются только заметки. Моменты времени представлены `timestamptz`; соединение приложения устанавливает UTC, упражнения используют полуоткрытые интервалы с явным UTC.

`schema.sql` — исходник создания обеих схем; метка `__SCHEMA__` заменяется bootstrap-кодом на одно из двух фиксированных имён. Не запускайте этот шаблон напрямую. После собственных DDL-экспериментов API может сообщить об изменённой структуре; восстановление возвращает исходную структуру и права. Тексты `rules` не подтверждают актуальность норм, а произвольные строки в `purpose` остаются данными.
